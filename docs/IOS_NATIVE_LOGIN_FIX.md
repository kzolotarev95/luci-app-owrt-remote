# Вход из ярлыка iOS: документная навигация — локальная v125

В режиме приложения с домашнего экрана вход теперь выполняется обычной
отправкой HTML-формы и серверным редиректом. До этого он выполнялся через
`fetch`, после которого JS открывал главную страницу.

Проверка 2FA и подготовка reCAPTCHA сохранены. Для reCAPTCHA v3 отправка формы
происходит после получения свежего токена. Проверки пароля, капчи и 2FA остаются
на сервере. В обычной вкладке браузера продолжает работать прежний сценарий.

Ответ HTML главной страницы теперь повторно выставляет постоянную HttpOnly
cookie действующей сессии. Раньше это происходило только при входе, проверке
статуса и миграции старой сессии. Срок cookie согласован с продлённой серверной
сессией, `Secure` используется на HTTPS. Новые сессии при каждом открытии не
создаются. Явный выход и отзыв продолжают аннулировать доступ.

Ссылка манифеста стала постоянной: `/manifest.webmanifest`, без номера сборки
в URL. `id`, `start_url` и `scope` остаются `/`. Иконки сохраняют свои версии
для обновления изображения. Исправления атомарного хранения и восстановления
страницы из `IOS_SESSION_REOPEN_FIX.md` сохранены.

## Проверки

- Проверено чтением `/health` и `/api/session/status` на работающем VPS, что
  первый вариант исправления был установлен. Он не устранил наблюдавшийся
  пользователем выход на iPhone.
- `tests/test_ios_session_resume.cjs` проверяет теперь WebKit и Chromium,
  настоящий HTTPS на loopback и постоянный профиль браузера. Сертификат
  самоподписанный только в тесте; ошибки доверия игнорируются только там.
- Проверяются документный POST формы, постоянная Secure/HttpOnly cookie,
  закрытие браузера и перезапуск Hub, три дополнительных холодных открытия,
  восстановление старой формы, работа после офлайна и явный выход.
- HTTP-тест проверяет повторную выдачу cookie именно HTML-документом Hub,
  сохранение одной сессии и постоянную ссылку манифеста между сборками.
- Проверки формы 2FA и reCAPTCHA, включая свежий v3-токен при отправке формы
  из standalone-приложения, сохранены.

Запуск браузерной проверки из PowerShell с установленным Playwright:

```powershell
$env:NODE_PATH = Join-Path (Get-Location) '.test-output\tachyon-browser\node_modules'
$env:OWRT_TEST_ENGINE = 'webkit'
$env:OWRT_TEST_HTTPS = '1'
node tests/test_ios_session_resume.cjs
```

WebKit на Windows не является физическим iPhone. Причину конкретного поведения
системного окна iOS без наблюдения на устройстве полностью подтвердить нельзя.
После установки нужно обновить страницу в ярлыке iPhone, войти и проверить
смахивание приложения и повторный запуск. Коммит, push и установка на VPS
автоматически не выполнялись. Версия интерфейса остаётся v125.
