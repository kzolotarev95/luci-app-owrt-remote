# Пользовательское правило logrotate и статус неудачного обновления

Ошибка воспроизведена с правилом пользователя:

```text
/var/log/owrt-remote*.log {
    daily
    rotate 7
    size 50M
    missingok
    notifempty
    compress
    delaycompress
    copytruncate
}
```

Раньше установка отказывалась работать с любым `/etc/logrotate.d/owrt-remote`,
кроме точного старого правила Hub для `/var/log/nginx/*.log`. Обычное правило
для собственных логов Hub поэтому ошибочно считалось конфликтом.

Теперь пользовательский файл сохраняется и проходит обычную проверку
доверенного дерева logrotate: владелец/права, отсутствие symlink, разбор
правил и ограничение путей `/var/log`, затем штатный `logrotate --debug`.
Только точный старый дубликат nginx удаляется после создания резервной копии.
Проверки nginx, Certbot, SHA256 и результата ежедневного обслуживания сохранены.
Встроенный `HUB_LOG_MAINTENANCE_BUNDLE` и его SHA256 пересобраны.

На VPS статус failed имеет приоритет над совпадением версии. Кнопка красная:
«Повторить проверку» либо «Повторить обновление». Совпадение хеша сборки
не подтверждает завершение установки обслуживания. Повтор той же проверенной
сборки разрешён после failed; активная задача остаётся защищена от дублирования.
После подтверждённого успеха возвращается зелёное «Установлена последняя версия».

## Защита локального исправления от старой сборки GitHub

Опубликованная v125-r1 (хеш Hub начинается с `87eddb8c`) содержит прежний отказ
на пользовательское правило. Раньше несовпадения хешей хватало, чтобы предложить
её поверх локального исправления с тем же номером v125.

Теперь Hub объявляет `HUB_PACKAGE_RELEASE = 2`, синхронно с пакетной ревизией.
Источник без поля считается r1. Сравнивается пара «версия панели, ревизия»:
проверка, запуск и отдельный worker запрещают понижение. Номер интерфейса v125
сохраняется. Если в источнике более старая ревизия, зелёная кнопка показывает
«Установлена локальная версия», подсказка объясняет различие ревизий.
При публикации новой сборки r2 или следующей версии обновление доступно; исправления в пределах
одной ревизии по-прежнему определяются по SHA256.

При выпуске следующей версии интерфейса ревизию Hub и PKG_RELEASE нужно
синхронно сбросить на 1. Уже опубликованные теги не изменяются.

## Локальная установка и откат

В PowerShell Windows 11 укажите SSH-адрес именно проблемного VPS:

```powershell
$Vps = 'root@IP_ПРОБЛЕМНОГО_VPS'
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-logrotate-custom-fix.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps $Vps -Action Install
```

Скрипт устанавливает Hub/мобильный API с проверкой SHA и работающей ревизии,
затем проверенный компонент обслуживания. Один явный `run --force` проверяет
восстановление после неудачной попытки в те же сутки. Проверяются результат,
таймер, неизменность пользовательского конфига и `/health` запущенного Hub.
Старая failed-запись об обслуживании переносится в архив только после всех
этих проверок, под блокировкой обновления; другая активная задача не изменяется.

Резервные копии:
`/root/owrt-remote-backup-before-logrotate-custom-v125` и его `maintenance/`.
История failed сохраняется в `panel-update/job.failed-maintenance-*.json`.
Уже удалённые штатным обслуживанием архивы логов откатить нельзя.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps $Vps -Action Rollback
```

При ошибке установки настройки обслуживания и Hub восстанавливаются.
При явном откате старая failed-запись восстанавливается, если не появилась
другая задача обновления. Исправление включено в
[v125-r2](https://github.com/kzolotarev95/luci-app-owrt-remote/releases/tag/v125-r2).
Скрипт остаётся способом локального восстановления проблемной установки.

## Проверки

- Ubuntu 24.04, настоящие nginx/Certbot/logrotate/systemd в отдельной VM:
  исходная ошибка воспроизведена; install/run/rollback с предоставленным
  правилом прошли без изменения файла.
- Повтор текущей сборки через настоящий systemd worker завершился succeeded.
- Проверены локальный repair, архивирование failed, rollback и повтор repair.
- Проверены сохранность базы Hub, ключей, SSL-политики и прав error.log;
  недопустимый путь лога и symlink по-прежнему отклоняются.
- 17 тестов обслуживания прошли в Linux; на Windows 6 POSIX-сценариев пропущены.
- Все 32 теста обновления VPS, включая повтор, активный worker,
  проверку версий/ревизий и CSRF, прошли.
- Браузер, 1280/390 px: ошибка текущей сборки не становится зелёным current;
  проверка, подтверждённый retry, успешное восстановление и удаление старого
  pending ID после архивирования прошли.
- Более старая ревизия той же версии (включая старые сборки без поля ревизии)
  отклоняется до установки обслуживания, замены Hub/API и перезапуска.
  Следующая версия с r1 и исправления той же ревизии разрешены.
