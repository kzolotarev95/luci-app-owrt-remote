# NanoPi R3S, QEMU и загрузка модулей nginx — v125-r3

Netis NX62 отложен по просьбе пользователя: существующие запись и фотография
не изменялись. Для проверки конкретного устройства позже понадобится точная
строка поля «Модель» от агента.

## Изображения устройств

- Friendly NanoPi R3S: фото именно R3S из [каталога Armbian](https://www.armbian.com/nanopi-r3s/).
  Названия Friendly, FriendlyARM, FriendlyElec и board ID `friendlyarm,nanopi-r3s`
  сопоставлены явно. Фото подготовлено как прозрачный WebP 320×240.
- QEMU Standard PC: отдельная иллюстрация виртуальной машины, созданная для
  Hub. Это не фотография физического роутера. Поддержаны реальная строка
  `QEMU Standard PC (i440FX + PIIX, 1996)` и написание `1440FX + PIX` из запроса.
  [Описание виртуального PC в QEMU](https://www.qemu.org/docs/master/system/i386/pc.html).
- Источники, контрольные суммы и тип изображения сохранены в каталоге.
  Карточка и карта подключений используют один файл. Каталог и изображения
  синхронизированы в Android APK 0.3.13-v125.
- Неизвестные ревизии и похожие модели не подменяются изображениями других
  устройств; выбор не зависит от пользовательского имени роутера.

## Почему обновление VPS отказывало

Штатный пакет Ubuntu `libnginx-mod-http-geoip2` создаёт конфиг
`/usr/share/nginx/modules-available/mod-http-geoip2.conf` и ссылку на него
в `/etc/nginx/modules-enabled`. `nginx -T` включает этот файл, но прежняя
проверка отвергала любой разрешённый путь вне `/etc/nginx`, кроме политики
Certbot. [Состав пакета Ubuntu](https://packages.ubuntu.com/noble/amd64/libnginx-mod-http-geoip2/filelist).

Теперь только файлы вида
`/usr/share/nginx/modules-available/mod-<имя>.conf` разрешены для чтения,
если это обычный файл с владельцем root, без записи для группы/остальных,
размером до 16 КиБ и содержащий только директивы `load_module` со стандартным
путём к `.so`. Эти конфиги не изменяются и не включаются в список записываемых
файлов. Ссылка, ведущая за пределы разрешённых путей, по-прежнему отклоняется.
Произвольные `include`, конфиги сайтов и директивы логирования этим исключением
не разрешаются. Права на журналы не меняются.

Встроенный bundle обслуживания и его SHA256 обновлены. Ревизия панели и пакета
— 3, интерфейс v125. Это защищает исправление от замены более старой r2.
Исправление входит в [v125-r3](https://github.com/kzolotarev95/luci-app-owrt-remote/releases/tag/v125-r3).

## Установка и откат на VPS

PowerShell Windows 11; укажите SSH-адрес именно нужного VPS:

```powershell
$Vps = 'root@13.143.167.219'
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-models-nginx-fix.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps $Vps -Action Install
```

Проверяются загруженный Hub/API, SHA256 встроенного обслуживания, запуск
сервиса, результат очистки и таймер. Предыдущая ошибка обслуживания архивируется
только после подтверждённого восстановления. После установки обновите страницу.
Для фотографий устанавливать что-либо на физические роутеры не требуется.

Резервная копия: `/root/owrt-remote-backup-before-models-nginx-v125`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps $Vps -Action Rollback
```

Откат восстанавливает предыдущий Hub/API и настройки обслуживания. Архивы
журналов, уже удалённые штатным обслуживанием, восстановлению не подлежат.

## Проверки

- Chromium 320/390/1366/2560 px и WebKit 390 px: фотографии в карточках и карте,
  отсутствие мерцания при обновлении, сохранение имён, корректный fallback.
- Ubuntu 24.04 VM: установлены настоящие GeoIP2 и Stream из репозитория Ubuntu;
  прежняя ошибка воспроизведена, install/run/rollback прошли. Отдельный worker
  обновления Hub завершился `succeeded`; база, правило logrotate, SSL-политика,
  конфиги модулей и права журналов сохранены.
- 20 тестов обслуживания в Linux прошли без пропусков. Недопустимые внешние
  конфиги, небезопасные права и выход ссылки за пределы допустимых путей
  по-прежнему отклоняются.
