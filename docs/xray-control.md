# Remote управление Xray через Heartbeat

В карточке роутера на VPS кнопка **Remote управление Xray** открывает отдельную
вкладку. Доступны запуск, остановка, перезапуск, последний подтверждённый статус
Xray и журнал результатов. Доступ определяется правом управления выбранным
роутером (`G`). Дизайн и эффекты наследуются от панели Hub.

Нужны обновлённые Hub и агент на каждом управляемом роутере. Старая версия агента
отображается в этой вкладке с просьбой обновить её. Команды выполняются агентом
на роутере; пароль SSH и обратный Xray-туннель для доставки не нужны.

## Доставка и проверка результата

- Hub сохраняет команду в SQLite и возвращает её в ответе на следующий
  аутентифицированный Heartbeat **этого** роутера. Интервал Heartbeat сохраняется.
- Разрешены только `start`, `stop`, `restart`. Произвольный shell-код не принимается.
- Агент сохраняет идентификатор до исполнения и запускает ограниченный по времени
  обработчик procd. Повторная доставка того же идентификатора не повторяет команду.
- Остановка удаляет только instance `xray`. Instance `heartbeat` остаётся активным.
  Флаг `/etc/owrt-remote/control/stopped` сохраняет намеренную остановку после
  восстановления WAN и перезагрузки. Кнопка запуска снимает этот флаг.
- Перед запуском/перезапуском проверяется конфигурация. Ошибка проверки сохраняет
  действующий туннель. Успех старта подтверждается наличием процесса Xray, успех
  остановки — его отсутствием. Это подтверждение процесса, а не проверка всей
  цепочки доступа к LuCI/SSH.
- Итог приходит следующим Heartbeat. Получение команды не считается успехом.
  Если за три минуты нет доставки или результата, отображается соответствующий
  тайм-аут. Поздно доставленный итог принятой команды может подтвердить результат.
- После аварийного завершения обработчика/перезагрузки неопределённая команда
  не повторяется автоматически; агент сообщает о прерывании.
- История ограничена 100 командами на роутер, на странице видны последние 30.
  Действия также попадают в «Глобал логи». На роутере хранится только последний
  результат; вывод команды и блокировки находятся в `/tmp`, вывод ограничен.

## Журнал и время ожидания

Кнопка «Очистить логи» удаляет из этой вкладки завершённые записи и их вывод.
Последний результат сверху тоже очищается. Действующая команда остаётся видимой
и продолжает работу; глобальные логи и история других роутеров сохраняются.
Идентификаторы очищенных команд остаются в ограниченной таблице для защиты
от повторного выполнения. Повторные Heartbeat не возвращают очищенный вывод.

При запуске, остановке и перезапуске таймер обновляется каждую секунду без
дополнительных запросов к роутеру. Он показывает прошедшее время, приблизительное
ожидание ближайшего Heartbeat и результата, а также остаток общего лимита
в три минуты. Оценка учитывает сообщённый интервал Heartbeat и лимит обработчика
45 секунд. Это ориентир: при задержке сети результат может прийти позднее.
После завершения видна длительность ожидания и выполнения. Перезагрузка вкладки
не сбрасывает таймер; отсчёт привязан ко времени Hub, а не часам телефона.

Для установки только этой правки на VPS:

```powershell
$Fix = "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-control-ui.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps "root@179.43.187.107" -Action Install
```

Откат к панели, которая была перед этой правкой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps "root@179.43.187.107" -Action Rollback
```

Её отдельная резервная копия:
`/root/owrt-remote-backup-before-xray-control-ui-v121`. База данных при откате
файла не восстанавливается; очищенные результаты остаются очищенными.

Если полностью выключен сервис Remote, потерян интернет или Heartbeat не доходит
до Hub, канал доставки отсутствует. Остановка одного Xray этот канал не выключает.
Для обновления старого агента при уже неработающем туннеле нужен другой доступ к
роутеру; новая функция появляется после установки обновлённого агента.

## Установка локальной сборки из PowerShell Windows 11

Сначала VPS, затем каждый нужный роутер:

```powershell
$Fix = "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-control.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps "root@179.43.187.107" -Action Install
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router "root@192.168.2.1" -Action Install
```

Откат файлов из резервной копии:

```powershell
$Fix = "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-control.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router "root@192.168.2.1" -Action Rollback
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps "root@179.43.187.107" -Action Rollback
```

Копии находятся в `/root/owrt-remote-backup-before-xray-control-v121` отдельно
на каждом устройстве. Ошибка установки восстанавливает файлы, которые были до
текущей попытки. База Hub, ключи и настройки роутера при откате файлов сохраняются.

## Проверка на устройствах

1. Обновить вкладку Hub, открыть управление у выбранного роутера. Дождаться
   Heartbeat с подтверждением поддержки функции.
2. Остановить Xray и дождаться итога «Успешно». Проверить, что агент остаётся
   онлайн и время последнего Heartbeat обновляется.
3. При недоступных LuCI/SSH нажать «Запустить Xray» в открытой вкладке Hub.
   Дождаться подтверждения запуска, затем проверить LuCI/SSH.
4. Проверить перезапуск, журнал действий и «Глобал логи». Убедиться, что соседние
   роутеры продолжают работать.

Локальные проверки:

```powershell
python -m unittest discover -s tests -p "test_xray_control*.py" -v
```

Shell-тесты моделируют procd/Xray и выполняют настоящий обработчик в BusyBox ash,
если тестовый BusyBox доступен. Они не заменяют проверку на физическом OpenWrt.
