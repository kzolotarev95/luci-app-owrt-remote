# Скрытие блоков и вход Android — локальная v125

Исправлена ошибка первой установки: встроенная копия мобильного API в Hub
синхронизирована с `vps/mobile_api.py`. До этого старт Hub восстанавливал старую
копию, из-за чего конечная проверка файлов откатывала установку. Повторно
используйте ту же команду ниже; APK 0.3.4 менять не требуется.

Теперь установщик до резервного копирования и замены проверяет SHA256 и полное
совпадение встроенного и загруженного модуля. Несогласованная сборка отклоняется
до изменения VPS. Синхронизация исходников:
`python scripts/embed-mobile-api.py`, проверка:
`python scripts/embed-mobile-api.py --check`.

Повторная локальная проверка включает запуск настоящего Hub после замены
обоих файлов: встроенный модуль сохраняет исправленную политику Origin и не
меняет загруженный файл. Отдельные сценарии проверяют отказ до замены при
расхождении и автоматический откат при изменении файла после запуска.

У карты подключений, доступности роутеров и диска VPS теперь есть собственная
кнопка «Скрыть / Открыть». Заголовок остаётся доступен, содержимое действительно
скрывается. Три состояния независимы от общей статистики и запоминаются:
localStorage браузера и SharedPreferences Android. Опрос статусов не раскрывает
блок заново. Скрытая карта прекращает анимацию и возобновляет её при открытии.

Иконки рядом с картой и доступностью используют общий вид панели: схема сети
и линия активности золотого цвета. В Android добавлены нативные рисуемые значки,
в браузере проверены отображение и размеры SVG.

## Причина Request origin is not allowed

Нативный клиент отправлял синтетический заголовок `Origin` для POST. Сервер
мобильного API сравнивал его с вычисленным источником как строку. Например,
`https://hub.example:443` не совпадал с `https://hub.example`. При проксировании
также возможна разница между адресом клиента и внутренним адресом Hub.

Теперь Android не создаёт браузерный Origin. Проверки HTTPS, сертификата,
редиректов в пределах источника, сессии и CSRF-токенов остаются. Сервер продолжает
проверять Origin браузерных запросов, сравнивая схему, имя и эффективный порт.
Чужой домен, другой порт/схема, `null` и некорректные значения отклоняются.
Поддержка CORS не добавлена. Для исправления при неправильно настроенном
reverse proxy требуется обновить именно APK.

## Установка — PowerShell Windows 11

```powershell
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-dashboard-panels-mobile-login.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Install
```

Сохраняется отдельная резервная копия:
`/root/owrt-remote-backup-before-dashboard-panels-mobile-login-v125`.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Rollback
```

Android: локальная `artifacts/android/OWRT-Hub-Android-0.3.4-v125.apk`,
устанавливается поверх 0.3.3 с тем же ключом. Hub остаётся v125.

## Проверки

- Браузер: семь сценариев владельца и делегированных аккаунтов, ПК и мобильного
  вида, переключение трёх блоков, обновление данных и F5, сохранение подписи
  «Открыть», наличие иконок и отсутствие переполнения. Отдельно проверена карта
  на пяти размерах от 320 до 1920 px.
- 24 теста мобильного API: в том числе вход без Origin за proxy, стандартный
  порт 443, регистр домена и отклонение других источников. 67 JVM-проверок клиента
  и 176 проверок политики URL прошли.
- Android: сборка, lint без ошибок, сценарии эмулятора с явным запретом
  синтетического Origin на входе. Проверяются сворачивание трёх блоков,
  сохранение после перезапуска, иконки, остановка скрытой анимации и прежние
  сценарии панели.

Коммит, push, установка на VPS и проверка на реальном телефоне ещё не выполнялись.
