# Android: защита входа, Wake-on-LAN и компактная вёрстка

Все восемь изменений перечислены в
[CHANGES-0.3.8.md](../android/CHANGES-0.3.8.md). Работа локальная, версия
панелей остаётся v125. Новая APK — 0.3.8-v125.

## Включение защиты

В Android: «Настройки → Защита приложения → Включить защиту». Android попросит
подтвердить PIN, графический ключ или пароль, уже установленный на телефоне.
Если блокировка экрана не настроена, есть переход в системные настройки.
Для биометрии нужно заранее добавить отпечаток в Android; она включается
в этом же разделе приложения. Пароль аккаунта Hub и его 2FA остаются
отдельными настройками.

После ухода приложения в фон повторное открытие требует подтверждения.
Это распространяется на основной экран, настройки, терминалы, встроенный
браузер и резервные копии. Переходы между экранами внутри разблокированного
приложения повторную проверку не вызывают. Отмена и ошибка подтверждения
не открывают содержимое. После завершения процесса подтверждение требуется
снова; состояние разблокировки не сохраняется на диск.

Для отключения защиты тоже требуется подтверждение Android. При включённой
защите снимки экранов и предпросмотр задачи закрыты средствами FLAG_SECURE.
Перед повторным входом содержимое также закрывается непрозрачным слоем и
исключается из дерева доступности. Нет нового API, серверного PIN или
синхронизации параметров блокировки между устройствами.

Использованы штатные API Android:
[BiometricPrompt](https://developer.android.com/reference/android/hardware/biometrics/BiometricPrompt),
[KeyguardManager](https://developer.android.com/reference/android/app/KeyguardManager).

## Установка веб-исправления

Сама защита приложения и сохранение пароля Wake-on-LAN работают локально
на телефоне. Для уменьшения текста/стрелок и центрирования диска на веб-панели
обновите VPS текущей локальной сборкой:

```powershell
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-android-lock-layout.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Install
```

Резервная копия Hub и мобильного API:
`/root/owrt-remote-backup-before-android-lock-layout-v125`.
Установщик проверяет Python, запущенную ревизию и мобильный API.
Агент роутера для этих изменений обновлять не нужно.

Откат файлов из резервной копии:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Rollback
```

## Изменённые части

- Android `AppLock.java`, `HubApplication.java`, `NativeLockActivity.java`,
  `AppSecurityActivity.java`, manifest: настройка и проверка защиты всех Activity.
- `MainActivity.java`: пары значений, компактные стрелки, пункт защиты.
- `NativeRouterActivity.java`, `SshCredentialStore.java`: терминал и пароль WOL.
- `NativeSettingsActivity.java`: корона в информации о приложении.
- `vps/dashboard-vantage.css` и встроенная копия в `owrt-remote-hub.py`:
  компактные заголовки/стрелки, центрирование диска только на ПК.

Проверки используют изолированный Hub и эмулятор, без обращения к VPS/роутерам
пользователя. В эмуляторе временно настраивается тестовый системный PIN; в APK
его нет. На физическом телефоне проверка датчика отпечатка предстоит пользователю.

## Результаты проверок

- `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug` — успешно,
  ошибок lint нет; контрольная сумма и подпись APK проверены.
- `NativeRedesignInstrumentation` — 25 сценариев Android 15, включая
  компактные пары состояния, навигацию, терминалы и перестановку карточек.
  Дополнительный прогон перестановки выполнен на экране 320 dp со шрифтом 130%.
- `NativeDeviceSecurityInstrumentation` — сохранение/восстановление WOL,
  отсутствие пароля открытым текстом, разделение по роутерам/аккаунтам,
  сохранность рабочего пароля при неудачной команде и кнопка забывания;
  корона в «О приложении» и отсутствие отдельной надписи VPS в терминале.
- Системный PIN эмулятора: неверный PIN и отмена не включают защиту,
  правильный PIN включает её. После Home прямое открытие терминала закрыто
  непрозрачным слоем, доступностью и FLAG_SECURE до подтверждения Android.
  Отмена оставляет блокировку; правильный PIN открывает исходный экран.
- Отдельный новый процесс: холодный запуск снова требует подтверждение;
  отмена отключения оставляет защиту включённой, правильный PIN отключает её.
- Веб: восемь прогонов iOS-дашборда в Chrome/WebKit, 24 варианта дашборда
  шириной 320–2560 px, три прогона перестановки карточек — успешно.

Параметр сборки Android `-PnativeSecurity` выбирает отдельный тестовый runner;
флаг `-e coldResume true` проверяет запуск в новом процессе после основного
прогона. Эти проверки выполняются только на изолированном эмуляторе.
