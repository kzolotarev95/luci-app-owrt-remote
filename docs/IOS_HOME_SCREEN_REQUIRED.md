# Установка OWRT Hub на экран «Домой» для iOS — локальная v125

На iPhone и iPad панель открывается через ярлык домашнего экрана. В обычной
вкладке вместо формы входа или дашборда появляется отдельный экран установки:
общий логотип, сообщение «В браузере панель недоступна», три шага и кнопка
копирования ссылки. Кнопки обхода экрана нет.

Порядок: «Поделиться» → «На экран “Домой”» → «Добавить». Если iOS предлагает
«Открывать как веб-приложение», этот переключатель нужно включить. Если пункта
нет в текущем браузере, экран предлагает открыть ссылку в Safari. Сайт не может
сам нажать системную кнопку добавления ярлыка. Инструкция сверена с
[руководством Apple](https://support.apple.com/guide/iphone/bookmark-a-website-iph42ab2f3a7/ios).

При запуске через ярлык открывается обычная авторизация, затем панель. ПК,
Android, heartbeat агента и API продолжают использовать прежние маршруты.
Исправления сохранения iOS-сессии из `IOS_NATIVE_LOGIN_FIX.md` остаются.

## Реализация

- Сервер отдаёт установочный HTML для основных документов Hub по iPhone/iPad
  User-Agent до генерации формы входа и дашборда. Это работает и при наличии
  действующей сессии. Старую форму нельзя отправить POST `/login` до установки.
- При старте установленного приложения `navigator.standalone` или
  `display-mode: standalone` разрешает открыть целевой документ. Cookie
  `owrt_remote_ios_app` хранит только подсказку интерфейса, не токен входа.
- Ранний скрипт в head проверяет реальный режим окна. Обычная вкладка скрывает
  документ и переходит к установке, даже если подсказка скопирована из приложения.
  iPad с настольным User-Agent определяется по Mac-платформе и touch-точкам.
- Установочный экран не запускает эффекты, авторизацию, long-poll или опросы.
  Если cookies запрещены, приложение показывает причину без цикла редиректов.
  Возврат разрешён только на известные относительные маршруты Hub.
- Ссылки на страницы того же Hub с `target="_blank"` в приложении iOS открываются
  в текущем окне, чтобы SSH, заметки и настройки не попадали обратно в браузер.
  Внешние ссылки и загрузки сохраняют обычное поведение.
- Для манифеста и иконок сохранены публичные URL. Страница установки не требует
  входа. Манифест запускает приложение с `/`.
- Это ограничение способа отображения, а не дополнительный механизм защиты.
  Доступ к данным по-прежнему проверяется серверной сессией и правами.

## Проверки

- Python: установочный HTML вместо входа/панели, маршруты документов и API,
  сохранение проверки сессии, недопустимые адреса возврата.
- WebKit и Chromium: Safari/Chrome/Firefox iOS, iPad с настольным UA, скопированная
  подсказка, standalone двумя способами, ПК/Mac/Android и отключённый JS.
  Проверены отсутствие формы и фоновых запросов за экраном, прямой переход
  в дашборд, копирование ссылки и ширины 320/390/1024 px. Снимки проверены.
- Повторный вход в WebKit через HTTPS с постоянным профилем: закрытие браузера,
  перезапуск Hub, ещё три открытия, офлайн и явный выход.

Физический iPhone и системное меню установки требуют проверки пользователем.
Локальная версия остаётся v125. APK/пакеты, commit и push не выпускались.
