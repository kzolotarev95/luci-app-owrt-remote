# Повторное открытие Hub с экрана iPhone — локальная v125

Для дополнительного исправления после проверки на iPhone см.
[IOS_NATIVE_LOGIN_FIX.md](IOS_NATIVE_LOGIN_FIX.md): документный вход из ярлыка,
cookie в HTML-ответе и проверки WebKit через HTTPS. Использовать установщик
`deploy-ios-native-login.ps1` с отдельной резервной копией.

Исправлены две подтверждённые ошибки серверной логики:

- GET `/login` всегда показывал форму, даже когда cookie содержала действующую
  сессию. Теперь возвращается редирект в `/` с `Cache-Control: no-store`.
- Сессии сохранялись прямой перезаписью JSON без общей блокировки операций
  чтения/изменения/записи. Параллельные запросы могли увидеть недописанный файл
  или перезаписать сессии друг друга. В тесте до исправления из 24 одновременных
  новых сессий сохранялась одна (плюс исходная). Теперь операции сериализованы
  через `RLock`, а файл заменяется атомарно с сохранением прав `0600`.

На странице входа добавлена проверка текущей сессии при первом открытии,
`pageshow`, возврате из фона и восстановлении сети. Это возвращает в панель,
если приложение восстановило старый документ входа, а сессия ещё действует.
Используется небольшой GET `/api/session/status`; ответ не содержит токена.
Одновременно выполняется только одна проверка, есть тайм-аут и ограничение
повторных запусков. Ошибка сети не удаляет cookie и не создаёт бесконечный опрос.

Cookie получает согласованные `Max-Age` и `Expires`, сохраняя `HttpOnly`,
`SameSite=Lax` и `Secure` при HTTPS. Срок задаётся существующим
`OWRT_REMOTE_SESSION_TTL` (по умолчанию 30 дней). Явный выход, смена пароля,
истечение срока и отзыв сессии продолжают требовать повторного входа.

## Проверки

- До исправления воспроизведены потеря записей при параллельных входах,
  чтение недописанного JSON и показ формы при действующей сессии.
- `tests/test_session_persistence.py`: HTTP, атрибуты cookie, параллельные входы,
  атомарность файла, истёкшие/отозванные сессии и отзыв одновременно с touch.
- `tests/test_ios_session_resume.cjs`: настоящий локальный HTTP Hub, пароль
  и капча, постоянный мобильный профиль Chromium. Проверены закрытие браузера
  и перезапуск Hub, восстановление старой страницы входа, серия событий
  возобновления без параллельных проверок, отсутствие сети и явный выход.
- Проверки смены пароля, 2FA и мобильного API, а также семь браузерных сценариев
  формы с включённой/выключенной 2FA прошли.

Физический iPhone и его системное восстановление окна не тестировались.
После установки нужно один раз обновить страницу на iPhone, чтобы загрузился
новый код восстановления. Версия Hub остаётся v125. APK для этого изменения
не меняется. Коммит и push не выполнялись.

## Установка и откат — PowerShell Windows 11

```powershell
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-ios-session-fix.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Install
```

Резервная копия серверных файлов:
`/root/owrt-remote-backup-before-ios-session-fix-v125`.
Установка не удаляет и не сбрасывает существующие сессии.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Rollback
```
