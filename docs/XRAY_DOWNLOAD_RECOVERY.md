# Автоматическая установка и загрузка Xray

Исправление общее для OpenWrt с opkg/IPK и apk/APK. Версия интерфейса — v122.
Изменения включены в v122 и используются установщиком и агентом из GitHub.

## Что было неправильно

Наличие curl считалось достаточным: при его ошибке другие клиенты не запускались.
Без curl выбирался только один из uclient-fetch/wget. При этом wget часто является
ссылкой на uclient-fetch. Отказ предварительного HEAD исключал даже доступный
через GET пакет. Ошибка сети запускала перебор старых релизов и могла закончиться
сообщением об отсутствии совместимого Xray.

Лог GL-MT6000 подтверждает сбой загрузки, но не устанавливает его сетевую причину.
DNS, TLS, HTTP и сбой самого клиента различаются новой диагностикой на устройстве.

## Что изменено

- До замены файлов установщик проверяет curl, CA и jsonfilter. Недостающие пакеты
  устанавливаются через обнаруженный менеджер. Ошибка зависимостей останавливает
  установку отдельным этапом, до подготовки Xray.
- Установщик и агент используют один загрузчик, встроенный в оба файла. Исходник —
  `scripts/router-download.sh`; обновление встроенных копий —
  `python scripts/embed-router-download.py`, проверка — та же команда с `--check`.
- curl → uclient-fetch → wget: переход происходит после ошибки, ссылки на один
  исполняемый файл не повторяются. Частичные ответы удаляются. Секреты, URL с
  параметрами, подписанные адреса перенаправлений и сырые заголовки не печатаются.
- Для Xray выполняется GET без обязательного HEAD. Один файл имеет общий бюджет
  до 120 секунд на все клиенты и источники, подготовка Xray — до 300 секунд.
  Завершение процессов и уборка временных данных могут занять ещё несколько секунд.
- DNS/TLS/тайм-аут/403 останавливают перебор пакетов. Подтверждённый 404/410 позволяет
  проверить следующий опубликованный asset. Ошибки совместимости проверяют следующие
  кандидаты в пределах общего бюджета.
- Список релизов, имена файлов, размеры и SHA256 берутся из официального GitHub API.
  Сохраняются проверки формата, точной архитектуры/ABI, зависимостей целевой системы,
  версии и фактической поддержки VLESS reverse. Фиксированной версии пакета нет.
- Существующий исправный Xray используется повторно. Проверенная постоянная сжатая
  копия создаётся до замены бинарника; восстановление из неё не требует GitHub.
- Без настроек Hub установка возвращает успех и сообщает:
  «Установлено. Добавьте OpenWrt config из Hub для запуска туннеля».
  Существующие UCI и ключ веб-панели сохраняются.

В диагностике `http=000` означает, что клиент не сообщил HTTP-статус. Это не ответ
HTTP 000. Например, DNS-сбой curl показывает `tool=curl; http=000; rc=6; reason=DNS`.
`client_context` сохраняет отдельную причину ошибки контекста uclient: она сама по
себе не доказывает проблему TLS или нехватку RAM.

curl сохраняет разрешение DNS и привязку каждого перенаправления к выбранному WAN.
Резервные минимальные клиенты используют системный DNS, о чём агент сообщает при
WAN direct. Скрипты не меняют WAN/DNS/маршруты/Podkop/Xray transport.

## Зеркало

Готового доверенного зеркала проекта сейчас нет. По умолчанию используются только
официальные GitHub API/Assets; случайные публичные прокси не подключаются.
Полная недоступность GitHub без исправного локального Xray/кэша остаётся явной
ошибкой загрузки. Смена клиента не гарантирует обход сетевой блокировки.

Для будущего собственного HTTPS-зеркала предусмотрены `XRAY_PACKAGE_MIRROR`
в окружении или `owrtremote.main.xray_package_mirror` в UCI. Формат адресов:
`https://YOUR-MIRROR/xray/vVERSION/PUBLISHED_ASSET_NAME`. Адрес не должен содержать
пароль, query или fragment. Ожидаемая SHA256 всё равно берётся из официального API;
метаданные зеркало не подменяет. При включённом зеркале первая половина бюджета
файла отведена официальному источнику, вторая остаётся для зеркала.

## Локальная проверка на роутере

PowerShell Windows 11; отдельная установка исправления на существующий клиент:

```powershell
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-xray-download-fix.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router root@192.168.2.1 -Action Install
```

Скрипт сохраняет агент в
`/root/owrt-remote-backup-before-xray-download-v121`, устанавливает новый агент и
выполняет `prepare-xray`. При ошибке автоматически восстанавливает прежний агент.
Рабочий Xray, проверенный кэш и настройки не удаляются. Действующий туннель
скрипт не перезапускает. Если первая установка прервалась до создания web.key,
ключ создаётся только при его отсутствии.

Откат кода агента, с сохранением исправного бинарника и кэша:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router root@192.168.2.1 -Action Rollback
```

Для первичной установки из локальных исходников установщик также можно запускать
на роутере из копии проекта. Публичная однострочная команда не меняется:

```sh
wget -O - "https://raw.githubusercontent.com/kzolotarev95/luci-app-owrt-remote/main/install.sh?v=$(date +%s)" | sh
```

Диагностический режим установки включается переменной
`OWRT_REMOTE_INSTALL_DIAGNOSTIC=1` у процесса `sh`, исполняющего установщик. Он
показывает stdout/stderr этапов и коды возврата, без `set -x` и дампа UCI.

## Проверки

Регрессионные сценарии: отказ curl с успешным резервным клиентом; дедупликация
wget/uclient-fetch; сохранение исходного rc; DNS/TLS/ошибка записи; отсутствие HEAD;
остановка перебора при сетевой ошибке; 404; общий бюджет; зависший дочерний процесс;
официальная SHA256 при использовании зеркала; повреждённый пакет; сохранение
рабочего Xray и загрузочного кэша; установка и откат локального исправления.

Матрица выбора assets проверяет IPK/APK и точные имена aarch64, ARM, MIPS/MIPSel,
MIPS64, i386 и x86_64. Она не означает, что upstream публикует пакет для каждого
теоретического имени CPU. Если соответствующего asset нет, чужая архитектура
не подставляется. Прогоны BusyBox ash и реальные роутеры отмечаются отдельно;
полный физический прогон на всех CPU не заявляется.

Результаты локального прогона 21.11.2026:

- Linux BusyBox ash 1.36.1: 38 проверок успешны, включая 22 комбинации
  точных архитектур и форматов в одной проверке матрицы.
- Windows POSIX shell: в основном прогоне bootstrap/выбора релизов/установщика
  55 тестов прошли, 2 требуют Linux; дополнительные проверки упаковки и локального
  развёртывания также успешны.
- Реальная HTTPS-загрузка официального release asset размером 12 243 318 байт
  через новый код прошла с HTTP 200; SHA256 совпала с GitHub API. Этот файл
  использован только для проверки скачивания, на роутер он не устанавливался.
- Установка на проблемный физический GL-MT6000 / OpenWrt 25.12.6 ещё не выполнена.
