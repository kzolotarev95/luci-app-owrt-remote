# Проверка обновления панели роутера: POST и uhttpd

Причина отказа v125-r1: JS отправлял `X-OWRT-Panel-Update: 1`, а CGI ожидал
`HTTP_X_OWRT_PANEL_UPDATE=1`. Штатный OpenWrt uhttpd экспортирует в CGI только
фиксированный список заголовков. Произвольный `X-OWRT-Panel-Update` в него
не входит; Hub передаёт заголовок, но uhttpd не создаёт переменную окружения.
Источник: [uhttpd proc.c, proc_header_env](https://github.com/openwrt/uhttpd/blob/master/proc.c).

## Исправление

- Авторизованная страница содержит подтверждение, полученное SHA256 от
  доменного префикса и текущего web.key. Сам web.key этим полем не раскрывается.
- JS передаёт подтверждение в теле POST, сохраняя URL панели, ключ и префикс
  `/access/<id>/`. Подтверждение не добавляется в URL.
- CGI принимает его только из тела POST. GET, неверный ключ, неверное
  подтверждение и подтверждение только в query не запускают обновление.
- Прежний заголовок поддержан для CGI-серверов, которые его экспортируют;
  зависимость от его наличия в uhttpd устранена.
- JS получил новый ключ кэша; SHA256 манифеста пересчитаны.
  Пакетная ревизия — 125-2 (выпуск v125-r2), интерфейс остаётся v125.
- Статус «Установлена локальная версия» отображается зелёным на верхней
  кнопке и в окне обновления, включая зимнее и облегчённое оформление.

Прежние проверки не проходили через uhttpd: браузерный тест перехватывал
запрос, а тест CGI сам задавал переменную `HTTP_X_OWRT_PANEL_UPDATE`.
Регрессия теперь проверяется реальным HTTP-запросом к uhttpd в отдельной
OpenWrt VM, включая отклонение неподтверждённых запросов.

## Установка — PowerShell Windows 11

```powershell
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-router-update-post-fix.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router root@192.168.2.1 -Action Install
```

После установки обновите страницу роутера через Ctrl+F5 (на телефоне
закройте и откройте страницу) и нажмите «Проверить обновление».
Если локальная ревизия выше ревизии источника, нормален зелёный статус
«Установлена локальная версия»: установка старой ревизии пропускается.
При совпадении с опубликованной сборкой — «Установлена последняя версия».

Резервная копия семи файлов UI/обновления:
`/root/owrt-remote-backup-before-router-update-post-v125`.
Откат:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router root@192.168.2.1 -Action Rollback
```

Настройки UCI и Xray этим установщиком не заменяются. Исправление включено
в [v125-r2](https://github.com/kzolotarev95/luci-app-owrt-remote/releases/tag/v125-r2).
На уже установленной r1 с POST-ошибкой для первого перехода можно также
использовать новый пакет через LuCI/SSH или раздел Hub «Обновить роутеры».

## Результаты проверки

- Реальная OpenWrt 25.12.6 VM с uhttpd: отсутствие произвольного заголовка
  воспроизведено; check/install с подтверждением в POST проходят. Запросы
  без подтверждения, с неверным значением и значением только в URL отклонены.
- Та же VM: загрузка с SHA256, сохранение конфигурации и кэша Xray,
  откат при ошибке службы, восстановление прерванной транзакции и проверка
  повреждённой резервной копии прошли.
- Все 17 тестов обновления/установщика и 24 теста упаковки прошли.
- Браузер: кнопка проверена на 1920/1366/390/320 px с прямым и прокси-URL;
  все 7 прежних сценариев интерфейса роутера также прошли.
- SHA256 манифеста и подготовка установщика/отката проверены локально.
