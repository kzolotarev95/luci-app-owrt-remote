# Версия Tachyon и удаление нод — локальная v125

## Что было причиной

На роутере 192.168.2.1 (OpenWrt 24.10.4) проверено:

- `/usr/bin/tachyon --version`: `tachyon 2.0.0-rc.5`;
- веб-интерфейс на 1680: `Tachyon v2.0.0-rc.5`;
- opkg: `Version: 2.0.0~rc.2-1`;
- публичные agent health/OpenAPI закрыты ответом 401.

Внутреннее обновление Tachyon заменило бинарник, оставив прежнюю запись opkg.
Агент Hub брал эту запись, поскольку защищённый API не отдавал версию.

Теперь сначала читается `tachyon --version` с тайм-аутом 3 секунды и строгой
проверкой результата. Версия `tachyon-core` не принимается за версию панели.
opkg/APK остаются источником `package_version`; при недоступном бинарнике
сохраняется прежний путь определения версии через API/пакет. Обнаружение
не запускает службу Tachyon, не меняет её настройки и не скачивает обновления.
При замене бинарника его размер/mtime/inode сбрасывают 30-секундный кэш
обнаружения, поэтому следующее чтение не сохраняет старую версию после апдейта.

Новый детектор проверен временным запуском на настоящем роутере без замены
установленных файлов: вернул `version=2.0.0-rc.5`,
`package_version=2.0.0~rc.2-1`, доступность панели подтверждена.
Поддержаны обе схемы пакетов: opkg для 23.05/24.10, APK для 25.12.
Физические устройства с 23.05 и 25.12 отдельно не проверялись; эти варианты
проверены shell-тестами с соответствующими ответами менеджеров пакетов.

## Удаление и повторное создание

Раньше удаление меняло только `deleted_at`. Следующий heartbeat безусловно
сбрасывал его, возвращая карточку. `upsert_router()` затем наследовал поля
удалённой записи: имя, статус, заметки, UUID и состояние Tachyon.

Теперь:

- Удаление очищает имя, группу, заметки с изображениями, last_seen, статус,
  состояние Tachyon и VPS host, историю доступности, команды Xray и счётчики.
- Закрываются HTTP-терминалы этой ноды, удаляются её кэшированные страницы
  и старые делегированные права. Другие роутеры сохраняют данные и права.
- В браузере удаляются черновики этой карточки и запомненный пароль Wake-on-LAN.
- В БД остаётся пустая отметка с ID, чтобы старый агент не зарегистрировал
  удалённый ID автоматически. Обычный heartbeat отметку не снимает.
- Явное создание того же ID начинает новую запись с новыми UUID и пустыми
  данными. Обрабатываются и отметки удаления, оставленные старыми версиями Hub.
- Повторно созданная нода принимает heartbeat только с SHA256-отпечатком её
  нового ключа. Агент вычисляет его из UCI `vless_uuid`; сам ключ в heartbeat
  не передаётся и отпечаток не записывается в публичный status_json.
- Запоздалые старые heartbeat и результаты команд не меняют новую ноду и не
  получают её новые команды. Запись защищена SQLite-транзакцией и UUID записи.
- Уже существующие активные ноды продолжают принимать старые агенты.
- Ошибка очистки возвращается в панели, успех при ошибке не показывается.

**После удаления и создания того же ID нужно применить новый «OpenWrt config»
на роутере с обновлённым агентом.** До этого новая карточка остаётся пустой
и офлайн. Сброс настроек OpenWrt на самом устройстве не выполняется.

## Изменённые исходники

- `files/usr/lib/owrt-remote/tachyon.sh`: чтение реальной версии бинарника.
- `files/usr/sbin/owrt-remote`: отпечаток экземпляра в heartbeat.
- `vps/owrt-remote-hub.py`: очистка, защита от восстановления и новый экземпляр.
- `vps/deploy-tachyon.ps1`: отдельная резервная копия v125 для роутера.
- `vps/deploy-tachyon-node-lifecycle-fix.ps1`: общий локальный установщик.
- `tests/test_tachyon.py`, `tests/test_router_deletion.py`: проверки обоих багов.

## Установка в PowerShell Windows 11

Сначала VPS, затем агент основного роутера:

```powershell
$Fix = Join-Path $env:USERPROFILE 'Documents\openwrt overlay\vps\deploy-tachyon-node-lifecycle-fix.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Install
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router root@192.168.2.1 -Action Install
```

Резервные копии:
`/root/owrt-remote-backup-before-tachyon-node-lifecycle-v125` на каждой машине.
На роутере сохраняются агент и helper, на VPS — Hub и модуль мобильного API.
После установки агента очередной heartbeat обновит версию в карточке.
Для другого роутера применяется тот же Router-параметр с его адресом.

Откат исходников:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router root@192.168.2.1 -Action Rollback
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@13.143.167.219 -Action Rollback
```

Откат файлов не возвращает данные нод, которые пользователь уже удалил.
Новый столбец БД совместим с прежней версией Hub и сохраняется при откате.

## Проверки

- Живой OpenWrt 24.10.4: установленный бинарник и временный новый детектор
  подтвердили rc.5. Установленные файлы и конфигурация не менялись.
- Shell: старый opkg/APK, защищённый API, устаревший OpenAPI, некорректный вывод
  и отдельная версия core, SHA256 в реальном heartbeat_json без исходного ключа.
- SQLite/HTTP: удаление и повтор, 12 параллельных поздних heartbeat, пустое
  повторное создание, новые ключи, старые отметки удаления, новая привязка,
  удаление во время регистрации, недоставка команд старому экземпляру,
  очистка ресурсов и прав, отказ без owner и явная ошибка при сбое очистки.
- Проверки Tachyon/proxy/деплоя, доступности, управления Xray, смены VPS host,
  мобильного API и ресурсов выполнены отдельно.
- Браузер: удаление карточки очищает её черновики и сохранённый пароль;
  повторное появление пустой записи не возвращает заметки и пароль.
  Проверены семь режимов панели и восемь режимов раскрытия карточек.

Версия остаётся v125. APK не менялась. Установка исправления на реальные
машины, коммит, push и релиз не выполнялись.
