# OWRT Hub — нативное приложение Android

Тестовая версия **0.2.6-v124**, Android **8.0+**. Основные экраны состоят из
нативных View Android и работают через JSON API Hub. Дизайн: графитовая и зимняя
темы, Inter с кириллицей, нижняя навигация и отдельные экраны инструментов.

Изменения текущей сборки: [0.2.6](CHANGES-0.2.6.md). Предыдущий [аудит 0.2.1](AUDIT-0.2.1.md).

## Что работает нативно

- Подключение к своему HTTPS-домену/IP и порту, вход с капчей и условной 2FA.
- Обзор: реальные счётчики роутеров, история доступности за 24 часа, ресурсы VPS.
- Роутеры: поиск, онлайн/офлайн, группы, карточка устройства и переименование.
- Управление Xray через Heartbeat, ожидание с таймером, подтверждённый результат,
  история и очистка завершённых записей. SSH-туннель для этих команд не нужен.
- Заметки с фото, удаление выбранных записей владельцем Hub, Wake-on-LAN.
- Построчная SSH-консоль роутера и VPS: ввод, вывод, Ctrl+C, закрытие соединения.
- Конфигурация OpenWrt: команды подключения, копирование и сохранение .sh через SAF.
- Уведомления Hub, активные сессии, пароль и TOTP, пользователи и права A/B/G.
- Группы и назначение роутеров, добавление роутера, обновление Hub и очередь
  выборочного обновления/перезапуска роутеров с отдельными паролями и серверными результатами.
- Резервные копии: экспорт/импорт через системный выбор документов Android.
- Xray на VPS: обновление конфигурации и перезапуск сервиса.
- Оформление с эффектами «Потоки» и «Снег», данные подключения, выход и информация о приложении.

LuCI и Tachyon — самостоятельные веб-интерфейсы устройств: они открываются во
встроенном браузере инструментов. Главный экран приложения не является WebView.
Внешние ссылки оплаты/GitHub открываются системным браузером по нажатию.

## Подготовка Hub и установка APK

Мобильный API входит в текущий `main`, установщик VPS и обновление через кнопку
панели. Для старой сборки v123 сначала выполните «Обновление панели».
Текущий выпуск Hub — v124. Для смены VPS host через Heartbeat обновите также агент роутера.
Для удаления заметок в Android 0.2.4 нужен API ревизии 4 из текущего `main`
с маршрутом `/api/mobile/v1/router/<id>/notes/delete`. Установка и откат:
см. [CHANGES-0.2.4.md](CHANGES-0.2.4.md).

Ручная установка серверной части из локального checkout, PowerShell Windows 11
(замените `YOUR_VPS` адресом своего сервера):

```powershell
$Fix = Join-Path (Get-Location) 'vps\deploy-native-mobile-api.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@YOUR_VPS -Action Install
```

Скрипт загружает локальные файлы, проверяет Python, сохраняет резервную копию,
перезапускает Hub и проверяет ревизию и API. Если проверка не пройдена, он
восстанавливает предыдущие файлы. Успех: `NATIVE_MOBILE_API_Install_OK`.

Откат:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Vps root@YOUR_VPS -Action Rollback
```

Резервная копия: `/root/owrt-remote-backup-before-native-mobile-api-v123`.
Новый helper также включён в установщик VPS и в проверяемое обновление Hub.

Если установленная локальная сборка уже содержит API, а опубликованная сборка
ещё его не содержит, проверка обновлений пропускает несовместимый источник.
Панель сообщает причину обычным уведомлением; ошибка загрузки или повреждённая
контрольная сумма по-прежнему показываются как ошибки. После публикации
совместимой сборки следующая проверка снова может предложить установку.
Для исправления сообщения на уже настроенном VPS используйте
`vps/deploy-mobile-update-check.ps1 -Vps root@YOUR_VPS -Action Install`.
Откат: тот же скрипт с `-Action Rollback`. Его отдельная резервная копия —
`/root/owrt-remote-backup-before-mobile-update-check-v123`, чтобы сохранить
установленный ранее мобильный API. APK для этого исправления менять не нужно.

[Скачать готовую APK 0.2.6-v124](https://github.com/kzolotarev95/luci-app-owrt-remote/raw/refs/heads/main/android/apk/OWRT-Hub-Android-0.2.6-v124.apk).
Контрольная сумма — в [android/apk/SHA256SUMS](apk/SHA256SUMS).

Для самостоятельной сборки используйте раздел ниже. Результат —
`android/app/build/outputs/apk/debug/app-debug.apk`. Для обновления поверх
прежней APK используйте тот же ключ подписи. Локальная тестовая сборка
`OWRT-Hub-Android-0.2.6-v124.apk` подписана прежним ключом 0.2.0/0.2.1.
Готовая APK опубликована в [android/apk](apk/README.md) и [Releases v124](https://github.com/kzolotarev95/luci-app-owrt-remote/releases/tag/v124), отдельно от пакетов OpenWrt. В 0.2.6 добавлены Xray на VPS, выборочное обновление с отдельными паролями, эффекты и поиск устройств Wake-on-LAN. См. [изменения 0.2.6](CHANGES-0.2.6.md).
Откройте приложение, укажите свой адрес, например
`https://hub.example.com`, порт 443 или оставьте поле порта пустым. Вводите
учётную запись **Hub**, а не SSH/root-пароль VPS. Настройки старой WebView-версии
не мигрируются; при первом входе в нативную версию авторизуйтесь заново.

## Сессии, права и соединение

Пароль Hub не записывается на диск. SSH-пароли сохраняются только по переключателю,
отдельно от сессии, с шифрованием Android Keystore. Сессия, адрес и имя пользователя зашифрованы
AES-GCM с ключом Android Keystore. Резервное копирование данных приложения
отключено. Сертификат HTTPS проверяется системным хранилищем: обход ошибок
сертификата и произвольный HTTP запрещены. Debug HTTP разрешён только для
loopback-стенда. Сессия отзывается на Hub при выходе; при недоступности сервера
локальная сессия удаляется, а отсутствие подтверждения показывается явно.

Каждая операция проверяется сервером заново с правами текущего пользователя.
Скрытие кнопок не заменяет серверную проверку. Native API использует существующие
пароли, капчу, TOTP и cookie-сессии Hub; не отключает их ради приложения.
Опросы инструментов выполняются последовательно и прекращаются при уходе с
экрана; SSH PTY закрывается. Обновление карточек сохраняет прокрутку и поиск.

## Текущие ограничения и границы проверки

Это тестовая APK, подписанная прежним локальным debug-ключом, не релиз Google Play.
События Android доставляются через включаемый foreground-service и HTTPS long-poll к вашему Hub; Firebase/FCM не используется. После принудительной остановки или перезагрузки телефона откройте приложение, чтобы восстановить подключение. Ограничения энергосбережения зависят от телефона. Credential Manager/Passkey пока не реализован.
При reCAPTCHA сервер требует видимый веб-вход; после успешного входа приложение автоматически возвращается на нативный экран. Парольный вход с цифровой капчей и TOTP нативный.

SSH — построчная консоль, не полная эмуляция VT/xterm: для интерактивного vim/top
нужен отдельный полноценный терминал. Изображения заметок отображаются внутри приложения; есть прикрепление через
системный выбор документов. Фото уменьшаются и передаются в JPEG.
Архивы Hub ограничены 60 МиБ; импорт требует подтверждения владельца и заменяет
состояние Hub. На реальном VPS восстановление архива и команды обновления в
этой сессии не запускались. Действующие роутеры не перезагружались.

## Установка обновления и откат

Для удаления заметок нужен мобильный API ревизии 4: см. установку
и откат `deploy-android-note-delete.ps1` в [CHANGES-0.2.4.md](CHANGES-0.2.4.md).
Установите APK 0.2.6 поверх 0.2.5: подпись, имя пакета и формат зашифрованной
сессии сохраняются. Старую APK оставьте для отката.

При подключённом через USB телефоне с разрешённой отладкой, PowerShell Windows 11:

```powershell
$Repo = Join-Path $env:USERPROFILE 'Documents\openwrt overlay'
$Adb = Join-Path $Repo '.test-output\android-build-tools\sdk\platform-tools\adb.exe'
& $Adb -d install -r (Join-Path $Repo 'android\apk\OWRT-Hub-Android-0.2.6-v124.apk')
# Откат тестовой APK с сохранением данных:
& $Adb -d install -r -d (Join-Path $Repo 'artifacts\android\OWRT-Hub-Android-0.2.3-v123.apk')
```

Без ADB можно удалить новую APK и установить предыдущую, после чего войти
заново. Удаление приложения не меняет настройки VPS и роутеров.

## Сборка и проверки

```powershell
& .\android\build-support\build.ps1 -Tasks @('assembleDebug','assembleDebugAndroidTest','lintDebug')
& .\android\policy-tests\run.ps1 -JavaHome (Join-Path $PWD '.test-output\android-build-tools\jdk-17')
& .\android\client-tests\run.ps1
python .\tests\test_mobile_api.py
python .\android\test-fixtures\test_native_server.py
```

Используются JDK17, Gradle8.11.1, AGP8.9.2, SDK35/min26. Инструменты находятся в
игнорируемом `.test-output/android-build-tools`; подпись — в `.signing/`, она
не публикуется. Файл сборки: `app/build/outputs/apk/debug/app-debug.apk`.

Изолированный стенд содержит только фиктивные учётные записи, не исполняет
shell-команды и не обращается к VPS/роутеру. Запуск эмуляторного smoke:

```powershell
python .\android\test-fixtures\native_server.py --port 8766
# В другом окне PowerShell после запуска тестового AVD:
$Adb = Join-Path $PWD '.test-output\android-build-tools\sdk\platform-tools\adb.exe'
& $Adb -s emulator-5554 reverse tcp:8766 tcp:8766
& $Adb -s emulator-5554 install -r .\android\app\build\outputs\apk\debug\app-debug.apk
& $Adb -s emulator-5554 install -r .\android\app\build\outputs\apk\androidTest\debug\app-debug-androidTest.apk
& $Adb -s emulator-5554 shell am instrument -w -r -e fixtureUrl http://127.0.0.1:8766 ru.owrthub.app.test/ru.owrthub.app.NativeSmokeInstrumentation
```

Ожидается `OWRT_ANDROID_NATIVE_SMOKE_OK` и `INSTRUMENTATION_CODE: -1`.
Отдельные backend HTTP-тесты используют настоящий Handler Hub с изолированной
базой: проверяют капчу, TOTP, scope, CSRF, отзыв сессии, сохранение заметок,
конфигурацию и установку/откат helper. Эмулятор проверяет нативную навигацию,
вход, хранение сессии, поиск, инструменты и темы. Автотест стенда не заменяет
проверку настоящего SSH-туннеля и файловых операций на телефоне.
