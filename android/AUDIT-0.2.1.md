# Локальный аудит Android 0.2.1-v123

Проверены основные экраны и HTTP-контракты, обработка ошибок, смена аккаунта,
пауза/возобновление, поворот, очередь команд и фактическая передача документов.
Исправления относятся к Android-клиенту; версия панели остаётся v123.

## Найденное и исправленное

| Проблема | Исправление |
| --- | --- |
| Точная причина отказа API заменялась общим HTTP-кодом | Показывается ограниченный текст ошибки, включая plain-text ответы старых маршрутов. Типы 401/403 сохраняются. |
| HTTP 200 с `ok:false` мог считаться успехом | Такой ответ теперь отклоняется и показывает причину. |
| Поздний ответ старого экрана мог стереть/перезаписать новый вход | Условные операции с записью сессии, общий lock и проверка соответствия ответа текущему cookie. |
| В разных Activity оставались разные копии сессии | Клиент сверяет общий зашифрованный store перед запросами. |
| Старое окно могло отправить действие после смены аккаунта | Перед записью проверяется исходный контекст сессии; команда не отправляется молча под новым аккаунтом. |
| После перезапуска Hub менялись служебные CSRF-токены | Перед командами обновляется сессия и токены; автоматического повторного запуска команды нет. |
| При возврате из настроек отображались устаревшие права и данные аккаунта | Выполняется перепроверка сессии; при смене аккаунта очищаются старые карточки, ресурсы и фильтры. |
| Отозванный доступ оставлял старые данные/управление инструментом на экране | Права обновляются, данные скрываются при отказе доступа, запрещённый опрос останавливается. |
| Сбой ресурсов VPS или групп мешал обновлению всех роутеров | Обязательные и дополнительные данные обрабатываются отдельно, причина частичного результата показывается. |
| После неудачного стартового соединения не было явного повтора | Добавлена кнопка повторного подключения. |
| Офлайн-роутер с прежним `running` увеличивал счётчик запущенных Xray | В счётчик входят только роутеры с действующим Heartbeat. |
| График соединял линией пропуски, которые сервер помечал отсутствием замеров | Используется серверный `gap_after`; разрыв проверяется по фактическому изображению графика. |
| Поворот пересоздавал формы и терял черновики | Экран и введённые данные сохраняются при смене ориентации. |
| Переключение в аутентификатор сбрасывало настройку 2FA | Ticket и ключ остаются только в памяти защищённого экрана; пароль/код очищаются, включение можно завершить после возврата. |
| Ошибки длинных форм оказывались выше видимой части страницы | Сообщения закреплены отдельно от прокручиваемой формы. |
| Вход с reCAPTCHA оставлял лишнюю парольную форму/дубли кнопок | Показывается один защищённый веб-вход, после успеха происходит возврат в нативный интерфейс. |
| Сбой renderer веб-инструмента мог приводить к NPE | Приложение закрывает инструмент и возвращает управление нативному экрану. |
| Веб-инструменты игнорировали выбранную тему | Используется текущая палитра приложения. |
| Проверка gzip ограничивалась двумя первыми байтами | Проверяется весь поток и CRC, с ограничением распакованного размера. Повреждённый архив не отправляется. |
| После недоступности Hub экран копий оставался без повтора | Добавлена повторная проверка доступа и конкретные причины ошибок. |
| Неопределённый результат восстановления позволял слепо повторить операцию | Показывается отсутствие подтверждения; для новой попытки требуется повторная проверка доступа. |
| Можно было уйти с экрана копий во время операции | Назад ожидает результат; операция продолжает работать при обычном уходе приложения в фон. |
| Временные архивы могли остаться после завершения процесса Android | Старые файлы только этого инструмента очищаются при следующем открытии. |
| Смена аккаунта при экспорте могла сохранить старые данные или затереть новую сессию | Перед сохранением проверяется сессия; отказ экспорта перепроверяется через общий клиент. |
| Сохранение конфигурации не проверяло тип возвращённого URI | Запись допускается в документ `content://`, выбранный системным диалогом. |
| Android сообщал «обновлений нет» для несовместимого источника | Показывается причина несовместимости, полученная от Hub. |
| Состояния общей очереди показывались техническими английскими кодами | Основные состояния переведены в понятные подписи. |
| Длинное имя могло растянуть шапку | Заголовок и адрес ограничены одной строкой с сохранением полного имени в карточке. |
| Крупный системный шрифт раздвигал высоту счётчиков, сокращал навигацию и мог перекрыть подписи графика | Карточки выровнены по высоте, подписи навигации допускают две строки, легенда графика переносится с учётом размера текста. |
| Назад из оформления/подключения открывал другой раздел | Возвращает в настройки. |

## Проверка

Используется отдельный Android 15/API35 AVD и локальный стенд, привязанный к
127.0.0.1. В нём только фиктивные учётные записи и устройства. Команды не
исполняются, SSH-соединения и Wake-on-LAN-пакеты в реальные сети не отправляются.

Отдельный тестовый ContentProvider существует только в тестовой APK. Проверки
документов не ограничиваются открытием диалога: приложение читает и записывает
байты через ContentResolver. Проверяется gzip, точность импорта, SHA256 загрузки
из WebView, а также запись shell-конфигурации. Этот provider не входит в обычную APK.

Расширенный прогон:

```powershell
& .\android\build-support\build.ps1 -Tasks @('assembleDebug','assembleDebugAndroidTest','lintDebug','-PnativeAudit=true')
# После запуска изолированного стенда и установки APK на тестовый AVD:
& $Adb -s emulator-5554 shell am instrument -w -r -e fixtureUrl http://127.0.0.1:8766 ru.owrthub.app.test/ru.owrthub.app.NativeAuditInstrumentation
```

Обычный маршрут использует сборку без `-PnativeAudit` и
`ru.owrthub.app.NativeSmokeInstrumentation`. Он проверяет вход/неверную капчу и
OTP, поиск, карточку, Xray/результат/очистку, заметки, журналы, сессии, группы,
оформление, поворот и выход при недоступном сервере.

Журналы текущего локального запуска находятся в `.test-output/android-audit/`.
Итоговые числа и SHA256 поставляемой APK записываются в `artifacts/android/`.

## Практические границы

Проверка на эмуляторе подтверждает клиентские сценарии и контракт локального
стенда. Реальное восстановление боевого VPS, прошивка/перезапуск действующих
роутеров и аппаратные различия Android 8–14 в этом прогоне не проверялись.
Ограничения функций (построчная консоль, отсутствие Android push/Passkey и
редактора фотографий) перечислены в README; они не объявляются исправленными.
