# Применение OpenWrt config через панель роутера (v120)

При отправке textarea браузер кодирует переносы строк как CRLF. CGI
декодировал их без нормализации и записывал CR в исполняемый shell-скрипт.
После появления блока `if/then/else/fi` для сохранения ручного VPS host
это приводило к ошибке `unexpected end of file (expecting "then")`.

CGI удаляет CR перед записью скрипта и проверяет целиком `sh -n` до
выполнения любых команд UCI. При ошибке синтаксиса конфигурация не
меняется. Выполнение через `sh -e` останавливается при ошибке команды,
например при неудачном `render-client`, и не продолжает перезапуск.

`tests/test_xray_apply.py` отправляет настоящий URL-encoded POST в CGI
с тестовым ключом и исполняет команды строгой POSIX-оболочкой. Проверяются
CRLF и LF, heredoc, пустые строки, кодированные символы, отклонение
неполного скрипта до изменений, остановка при сбое команды и отказ
без авторизации. Полный конфиг, сгенерированный Hub, применяется через
ту же форму с подменёнными UCI/службой; ручной VPS host и WAN сохраняются.
На Windows строгая проверка использует Git for Windows dash.

## Установка и откат

Скрипт обновляет только CGI на роутере. VPS обновлять для этого фикса
не требуется. До замены сохраняется первая резервная копия CGI:
`/root/owrt-remote-backup-before-xray-apply-v120/owrt-remote`.

Из PowerShell Windows 11; замените IP, если адрес роутера отличается:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-apply-fix.ps1" -Router "root@192.168.2.1" -Action Install
```

После `XRAY_APPLY_ROUTER_Install_OK` обновите панель роутера через
Ctrl+F5, снова скопируйте полный блок **OpenWrt config** из панели VPS
и нажмите **Применить настройки**. Это повторно применит настройки без
CR и пересоберёт Xray-конфиг. Предыдущая неудачная попытка могла успеть
записать часть настроек; замена CGI сама по себе их не переприменяет.
Если после успешного применения ошибка proxy остаётся, требуется
проверка запуска Xray и обратного соединения с VPS на реальном роутере.

Откат возвращает CGI до установки; настройки, повторно применённые
через форму, остаются текущими:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-apply-fix.ps1" -Router "root@192.168.2.1" -Action Rollback
```

Проверки локально:

```powershell
python tests/test_xray_apply.py -v
```

Переносы строк в формах описаны в [стандарте HTML](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html).

## Мобильная вставка команд (локальный фикс v120)

Воспроизведён отдельный случай `rc=255`: в строке
`uci set owrtremote.main.router_name=‘Дом у моря’` типографские кавычки
не являются кавычками shell. UCI получает лишние аргументы, хотя `sh -n`
не находит ошибки. По одному коду нельзя утверждать, что это причина
конкретного сбоя на телефоне; необходима проверка исходного блока.

В поле команд отключены автокоррекция, автоматический регистр и
автозаполнение. Перед применением удаляется начальный UTF-8 BOM;
в отдельных строках `uci set owrtremote.main...` исправляются неразрывные
разделители и внешние парные типографские кавычки. Содержимое значения
экранируется как буквальная строка: `$`, обратные кавычки и апострофы
не становятся командами. Значения в обычных shell-кавычках, многострочные
строки и heredoc не переписываются. При ошибке вставленный текст остаётся
в поле; настоящие ошибки выполнения по-прежнему останавливают скрипт.

Дополнительные тесты проверяют воспроизведение `255`, исправление мобильной
типографики, сохранение Unicode-значений, отсутствие исполнения символов
из значения, экранирование текста ошибки в HTML и сохранение остановки
при настоящей ошибке UCI.

Обновляется только `/www/cgi-bin/owrt-remote` на роутере, без перезапуска
служб и изменений настроек при установке. Резервная копия отдельная:
`/root/owrt-remote-backup-before-xray-mobile-v120/owrt-remote`.

Установка из PowerShell Windows 11:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-mobile-fix.ps1" -Router "root@192.168.1.1" -Action Install
```

После `XRAY_MOBILE_ROUTER_Install_OK` обновите страницу на телефоне,
снова вставьте полный блок **OpenWrt config** и примените его.

Откат CGI (применённые через форму настройки остаются текущими):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-mobile-fix.ps1" -Router "root@192.168.1.1" -Action Rollback
```

Проверки установки и отката выполняются на временных файлах без SSH:

```powershell
python tests/test_xray_mobile_deploy.py -v
```


## Проверка Xray и ошибка Heartbeat после применения (локальный фикс v120)

В предоставленном журнале Xray 26.3.27 запускается успешно, а завершающая
команда `owrt-remote heartbeat` возвращает `rc=1` с `Failed to allocate
uclient context`. Это ошибка HTTP-клиента, не JSON и не переносов строк.
В старом `post_json` переменные `http_proxy`/`https_proxy` экспортировались
пустыми. uclient проверяет наличие указателя `getenv`, пытается создать
клиент для пустого адреса прокси и возвращает эту ошибку ещё до запроса.
Теперь переменные удаляются через `unset` в отдельной оболочке; внешний
процесс и его настройки прокси не изменяются, проверка TLS остаётся включённой.
Источник: [uclient-fetch](https://github.com/openwrt/uclient/blob/master/uclient-fetch.c).

При генерации проверяются UUID, диапазон портов 1–65535 и независимость
меток двух reverse-туннелей. Метки больше не изменяются через `safe_id`;
значение сохраняется буквально либо отклоняется с конкретной причиной.
JSON экранирует управляющие символы; порты записываются в десятичном виде,
в том числе при вводе с ведущими нулями. Идентификаторы пользователей и порт
сверены с генераторами клиента/сервера Hub в локальном тесте. Метки reverse
локальны для каждой стороны; они должны совпадать с правилами маршрутизации
своей стороны, а не обязательно иметь одинаковые имена на VPS и роутере.
Фактические настройки удалённого VPS этот локальный тест не проверяет.

Проверка меток и host не использует классы символов `tr`: в стандартной
сборке OpenWrt 24.10 `FEATURE_TR_CLASSES` выключен. Запись
`tr -d '[:space:][:cntrl:]'` там удаляет обычные буквы из названий классов
и ошибочно отклоняет корректный `reverse-in`. Используется явный диапазон
ASCII-пробела/управляющих байтов; исходные метки не меняются. Проверка пустого
поля CGI также использует явные пробельные символы. Регрессия воспроизводит
старое поведение без классов, проверяет обе метки из конфигурации Hub,
host и применение всего блока через POST с CRLF. Конкретные ключи из
пользовательского `cfg.txt` в тестах не сохраняются.
Источник: [настройки BusyBox OpenWrt 24.10](https://github.com/openwrt/openwrt/blob/openwrt-24.10/package/utils/busybox/Config-defaults.in).

Новый файл создаётся с правами 0600 в приватной папке рядом с рабочим JSON
и имеет расширение `.json`. До атомарной замены выполняется
`xray -test -config <candidate.json>`; используется фактический бинарник,
включая `/tmp/owrt-xray/xray`. Полный вывод и код Xray сохраняются. При
отказе временный файл удаляется, рабочий JSON не заменяется, следующие
команды блока (enable/restart/heartbeat) не выполняются. Проверка Xray
валидирует конфигурацию, но не подтверждает доступность VPS по сети.

CGI получает этап выполнения от агента. Ошибка Heartbeat показывается
отдельно, с настоящим выводом HTTP-клиента и указанием, что предшествующие
команды уже выполнены. Реальная ошибка Xray показывается отдельно; общий
`rc=1` больше не сопровождается советом о переносах строк. Проверка
синтаксиса `sh -n` и мобильная нормализация сохраняются. При любом отказе
вставленный блок остаётся в поле; уже записанные UCI-настройки не откатываются
автоматически, что явно указано в сообщении.

Новый скрипт `vps/deploy-xray-validation-fix.ps1` обновляет CGI и агент,
не пересобирает настройки и не перезапускает службы при установке/откате.
Первая резервная копия обоих файлов:
`/root/owrt-remote-backup-before-xray-validation-v120`. Если установка
оборвалась или проверка файлов не прошла, возвращаются файлы до этой попытки.
На роутере друга нужно указать его доступный SSH-адрес вместо локального IP.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-validation-fix.ps1" -Router "root@192.168.2.1" -Action Install
```

Откат кода (настройки, уже применённые через форму, сохраняются):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-validation-fix.ps1" -Router "root@192.168.2.1" -Action Rollback
```

Дополнительные тесты: `tests/test_xray_validation.py` и
`tests/test_xray_validation_deploy.py`. Для проверки реальным Xray задайте
`OWRT_TEST_XRAY_BIN`; проверялась версия 26.3.27 (Windows amd64), включая
настоящий отказ неподдерживаемого `flow` с кодом 23. Отдельный mock проверяет
ошибку с кодом 1, который тоже должен сохраняться без подмены причины.
