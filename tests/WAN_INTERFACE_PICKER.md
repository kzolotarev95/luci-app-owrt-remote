# Несколько WAN интерфейсов и резервирование (v112)

Кнопка **Выбрать интерфейсы** раскрывает список с галочками. Можно отметить
один, два, три и больше интерфейсов. Список содержит имена
логических интерфейсов OpenWrt. Он собирается при открытии страницы из
конфигурации `network` (UCI) и списка netifd (`ubus network.interface dump`).
Поэтому доступны и настроенные, но ещё отключённые 4G/Wi-Fi интерфейсы.
Повторяющиеся имена объединяются. Текущее значение остаётся выбранным,
даже если интерфейс временно пропал из списка; пустое старое значение
означает `wan`.

**Сохранить и запустить** сохраняет весь выбранный список в существующей
настройке `owrtremote.main.wan_interface`, например `wan wwan modem4g`.
Уже сохранённые интерфейсы идут первыми в списке, поэтому добавление
резервных сохраняет прежний основной выбор первым. При запуске берётся
первый доступный интерфейс из сохранённого списка.
Пустой список при включённом прямом WAN отклоняется до изменения настроек.
Старое одиночное значение продолжает работать.

Remote использует один доступный интерфейс из выбранных. Доступность
определяется по `l3_device` netifd и IPv4 default route этого устройства.
Если текущий интерфейс отключился, при следующем heartbeat или событии
hotplug выбирается резервный. DNS и отдельная таблица маршрутов Remote
переводятся на него. Изменение привязки работающего Xray вызывает один
перезапуск обратных туннелей: одного изменения маршрутов недостаточно,
поскольку [Xray sockopt.interface](https://xtls.github.io/en/config/transports/sockopt.html)
привязывает соединение к конкретному устройству.

Рабочий резерв сохраняется, когда другой выбранный интерфейс возвращается.
Это предотвращает повторные разрывы при нестабильном основном канале.
При ручном перезапуске проверяется доступность выбранных интерфейсов заново.
Если все выбранные интерфейсы отключены, прямое подключение завершается
ошибкой; невыбранные интерфейсы и TUN-прокси в качестве резерва не используются.
Это резервирование по состоянию интерфейса и маршрута, без проверки доступа
в Интернет на стороне провайдера при остающемся поднятым интерфейсе.

Сетевые интерфейсы эта форма не создаёт и не перенастраивает. Список содержит
все логические интерфейсы; наличие `lan` в списке не означает, что он подходит
для WAN. LAN, dnsmasq и конфигурация Podkop не изменяются.

Установка из PowerShell Windows 11 (при необходимости заменить IP):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-wan-multi.ps1" -Router "root@192.168.2.1" -Action Install
```

Скрипт устанавливает CGI, LuCI, агент, WAN helper и hotplug вместе. До замены
сохраняются прежние файлы, UCI-настройки и Xray config в
`/root/owrt-remote-backup-before-wan-multi-v112`.
Успех подтверждает `WAN_MULTI_ROUTER_Install_OK`. После установки обновить
панель роутера через Ctrl+F5, отметить интерфейсы и сохранить выбор.
VPS обновлять не требуется. Старый `deploy-wan-interface-picker.ps1`
теперь вызывает эту же установку, чтобы новый интерфейс формы не
устанавливался отдельно от механизма резервирования.

Откат файлов и сохранённых перед установкой настроек:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-wan-multi.ps1" -Router "root@192.168.2.1" -Action Rollback
```

Успех отката подтверждает `WAN_MULTI_ROUTER_Rollback_OK`. Восстанавливаются
и настройки до установки, поэтому откат совместим с предыдущим агентом,
который поддерживал только одно имя WAN.

Локальные проверки:

```powershell
python tests/test_wan_interface_picker.py -v
python tests/test_wan_failover.py -v
python tests/test_xray_apply.py -v
```

Тесты выполняют настоящие CGI-запросы с подменёнными UCI/netifd и проверяют
список интерфейсов, сохранение нескольких выборов, недоступный uplink,
экранирование HTML и авторизацию. Тесты резервирования моделируют потерю
основного и двух первых каналов, выбор DNS резервного, маршруты, привязку
Xray и сохранение здорового резерва. PowerShell проверяется парсером и через `-PrepareOnly`;
это не выполняет SSH и не устанавливает файлы на устройство.

Источник API: [OpenWrt network.sh](https://git.openwrt.org/openwrt/openwrt/tree/?path=package%2Fbase-files%2Ffiles%2Flib%2Ffunctions%2Fnetwork.sh).
