# reCAPTCHA v3 в OpenWrt Remote Hub v112

В меню владельца, в блоке «Капча на экране входа», доступны цифры,
Google reCAPTCHA v2 Checkbox и Google reCAPTCHA v3. Установка обновления
сохраняет текущий режим и ключи. Для включения v3 выберите этот режим,
введите Site Key и Secret Key для **v3** и домена панели, затем сохраните
настройки с текущим паролем Hub.

При смене режима поля ключей очищаются. Для цифровой капчи они скрыты,
а после сохранения ключи удаляются из настроек на сервере. Для v2/v3
нужно ввести ключи выбранной версии; сервер не подставляет ключи другой
версии и отклоняет сохранение Google reCAPTCHA с пустыми ключами.
Удалённый текст полей больше не восстанавливается из-за обработки пустых
значений формы. Простое обновление формы сохраняет несохранённый ввод.

Порог оценки по умолчанию — 0.5, его можно изменить от 0 до 1.
Сервер отклоняет ответ с недостаточной оценкой, неверным доменом,
действием, отличным от `login`, отсутствующим или некорректным score.
Пароль и настроенная 2FA проверяются после капчи. При недоступности
Google вход по паролю показывает ошибку; другие способы входа остаются
доступны. Secret Key не попадает на публичную страницу входа.

Токен получается при отправке формы, а не при загрузке страницы.
Повторная попытка получает новый токен; повторный клик во время запроса
не отправляет второй вход. При ошибке или недоступности Google кнопка
снова становится доступной. На загрузку/ответ Google в браузере отведено
12 секунд, затем на запрос входа — 20 секунд.

Интеграция следует [документации Google v3](https://developers.google.com/recaptcha/docs/v3)
и [проверке токенов](https://developers.google.com/recaptcha/docs/verify).
Ключи v3 регистрируются в [консоли reCAPTCHA](https://www.google.com/recaptcha/admin/create).
Стандартный Google badge не скрывается.

## Проверки

```powershell
python -m unittest discover -s tests -v
python tests/test_recaptcha.py --export-js .test-output/recaptcha
node --check .test-output/recaptcha/login.js
node --check .test-output/recaptcha/dashboard.js
node tests/test_recaptcha_login.cjs .test-output/recaptcha/login.js
```

Python проверяет настройки, проверки ответа Google, совместимость v2/цифр,
отсутствие Secret Key в странице входа и настоящий HTTP `/login`
с разрешением/отказом до создания сессии. Ответы Google подменены;
настоящие ключи не нужны. Node проверяет получение свежего токена,
повторный вход, ошибки, timeout, двойной клик и сохранение настроек.
Реальную выдачу токена Google нужно проверить на домене VPS с ключами v3.

## Установка локальных изменений и откат

Из PowerShell Windows 11, находясь в корне репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "vps\deploy-recaptcha-v3.ps1" -Vps "root@YOUR_VPS_IP" -Action Install
```

Скрипт загружает локальный Python файл и тесты, проверяет их до замены
рабочего файла, сохраняет резервную копию, перезапускает `owrt-remote`
и проверяет health. База роутеров не заменяется. Установка не меняет
режим капчи: после неё v3 включается через настройки панели.

Откат при необходимости:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "vps\deploy-recaptcha-v3.ps1" -Vps "root@YOUR_VPS_IP" -Action Rollback
```

Откат восстанавливает Python файл и **только настройки капчи**, сохраняя
актуальный пароль, пользователей и другие параметры авторизации.
Это позволяет вернуть v2 вместе с прежними ключами после тестирования v3.
При неудачном запуске после установки/отката возвращается состояние
непосредственно перед попыткой. Резервные копии при повторном запуске
не перезаписываются:

* `/opt/owrt-remote/owrt-remote-hub.py.bak-before-recaptcha-v3-v112`
* `/opt/owrt-remote/captcha-before-recaptcha-v3-v112.json` (режим 0600).

Скрипт рассчитан на стандартные пути установленного Hub:
`/opt/owrt-remote/owrt-remote-hub.py`, `/var/lib/owrt-remote/hub-auth.json`
и health на `http://127.0.0.1:8088/health`.
