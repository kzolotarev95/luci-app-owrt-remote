# Обновление всех роутеров из Hub, v121

В меню владельца «Доступ к Hub» добавлен блок «Обновить все роутеры разом».
Ссылка «Открыть терминал обновления» открывает отдельную вкладку. В ней задаются
команда установки и один общий SSH-пароль root. При SSH-ключе поле можно оставить
пустым. Команда по умолчанию использует `RAW_REPO_BASE` именно этого Hub:
GitHub — GitHub, GitVerse — GitVerse.
Можно вставить полную shell-команду или прямую HTTP/HTTPS-ссылку на установочный
shell-скрипт с любого источника. Ссылка передаётся загрузчику как данные, включая
параметры запроса; скрипт сначала целиком скачивается, затем запускается.

Hub запускает одну очередь, по одному роутеру. Имя, заданное карандашом в Hub,
имеет приоритет в списке, текущей очереди и её результатах. Переименование
отображается в уже открытой вкладке при следующем опросе, примерно через 3 секунды.
Если имя в Hub не задано, оно берётся из Heartbeat (`owrtremote.main.router_name`)
и уточняется чтением UCI по SSH до подготовки установки. Например,
`router_id=node-5`, `router_name=АНТОН ВПН` показываются как «АНТОН ВПН»
и отдельно «ID: node-5». Если имя нигде не получено, выводится
«Имя роутера не получено», без подмены ID. Переименование в Hub не меняет UCI.
Неуспешное подключение, ошибка команды и отсутствие подтверждения различаются.
Если SSH отклонил общий пароль, у этого роутера выводится понятная ошибка
авторизации: его пароль может отличаться от общего. Обновление на нём не
запускается, очередь переходит к следующему. Запрет входа по паролю, отсутствие
SSH-ключа и сетевые ошибки отображаются отдельно; сам пароль не показывается.
`Connection timed out during banner exchange` означает, что SSH-приветствие
не поступило вовремя: до проверки пароля и отправки обновления дело не дошло.
По одной этой ошибке нельзя различить отказ обратного туннеля и SSH-сервера.
Панель показывает понятное объяснение и сохраняет технический ответ.
Надпись «Успешно — Советская 30» появляется только при полученном `rc=0`.
Код 0 подтверждает выполнение команды, а не проверку всех функций роутера.

Установка запускается отдельным процессом с `setsid` на роутере, не в shell VPS.
Перед запуском проверяются необходимые утилиты. Передача команды, имени и
ограниченного вывода не требует `base64`: команда записывается встроенным
`printf`, имя читается через UCI, вывод передаётся отдельным завершающим полем.
Строки установщика не могут подменить метаданные результата. Подтверждённая
ошибка подготовки отображается как «Ошибка» с причиной и текстом «Команда
обновления не запускалась»; неопределённость показывается при реальной потере
связи после отправки задачи.
При разрыве SSH во время установки Hub запрашивает результат по тому же ID,
не повторяя команду. Ожидание ограничено: запуск — 15 секунд, потеря связи SSH —
30 секунд, отсутствие нового вывода — 90 секунд, работа установщика — 180 секунд.
На роутере также действует собственный лимит 180 секунд, даже если VPS недоступна.
В карточке видны прошедшее время, пауза вывода, результат и причина ошибки.
Неудача одного роутера не останавливает очередь остальных. Если остановку нельзя
доставить из-за потери SSH, показывается «Не подтверждено», а не ложный успех.

«Остановить всё» сразу помечает оставшиеся устройства пропущенными, прерывает
текущий запрос SSH и отправляет текущей задаче остановку. На доступном роутере
установщик с дочерними процессами получает TERM, затем KILL при необходимости.
Это не откатывает изменения, уже внесённые установщиком. При отсутствии SSH
остановку невозможно подтвердить: действует локальный лимит задачи, очередь
показывает фактическую потерю связи. При недоступной сети продолжение следующих
роутеров может пересекаться с ещё не завершившейся задачей на отключённом роутере.

Временный каталог задачи расположен в `/tmp/owrt-remote-update-ID` на роутере;
вывод ограничен примерно 32 КиБ, на VPS передаётся хвост до 8 КиБ. После получения
результата каталог удаляется. При потере связи остаётся ограниченный результат
до следующей перезагрузки; нет постоянно работающего сборщика этой задачи.
У отменённой задачи после очистки остаётся только пустой маркер в RAM до
перезагрузки: он запрещает поздний запуск уже отменённого запроса из сети.
Новый API доступен только владельцу, POST защищён токеном и проверкой Origin.
SSH-пароль хранится только в памяти текущего worker, не в БД/журнале/URL/browser
storage. Из вывода удаляются пароль и строки с известными форматами секретов.

Закрытие вкладки не отменяет очередь. После открытия показывается текущее
состояние; результаты находятся в памяти VPS до двух часов после завершения.
Сводка очереди оформлена карточками: всего, обновляются, ожидают, успешно,
ошибки, не подтверждено, остановлено и пропущено. Полоса прогресса считает
обработанные устройства всех итоговых категорий; 100% не означает успех всех.
Под статистикой автоматически показывается подробный список роутеров с
ошибками, неподтверждённым результатом, остановкой или пропуском. Для каждого
видны имя с учётом переименования в Hub, отдельный ID, точная причина и раскрываемый вывод
команды, если он получен. Нажатие на соответствующую карточку статистики
оставляет только её категорию; «Показать все категории» возвращает общий
список проблем. Нулевой счётчик открывает понятное сообщение об отсутствии
устройств в категории. Список и счётчики обновляются вместе каждые три секунды,
выбранная категория, прокрутка и раскрытый вывод сохраняются. В новой очереди
снова показываются все проблемные результаты. Дополнительные запросы к
роутерам или повторная установка для просмотра списка не выполняются.
Мобильная вкладка терминала обновления адаптируется к ширине от 320 пикселей:
кнопки идут одной колонкой, карточки статистики — двумя, поля ввода имеют
шрифт 16 px, длинные имена, ID, команды и причины переносятся в своих блоках.
Списки и вывод команды ограничены по высоте; предусмотрены отступы safe area.
На ПК сохраняется прежняя центрированная колонка шириной до 1100 px:
ограничения для длинного текста не растягивают её на весь экран.
Заголовки и числа всех восьми карточек статистики, включая кнопки
«Подробнее», выровнены по центру на ПК и мобильном экране.
Пояснения к команде, паролю и остановке отделены от полей и кнопок одинаковыми
отступами. Кнопка «Обновить все по очереди» зелёная.
Рядом добавлена красная кнопка «Перезапустить все роутера». Она использует
тот же общий SSH-пароль, запускает отдельную последовательную очередь reboot
и не выполняет команду из поля обновления. Две очереди одновременно не работают.
Если имя не задано в Hub, оно уточняется из `owrtremote.main.router_name`
перед перезапуском каждого роутера.
Команда отправляется один раз в отдельном процессе с небольшой задержкой,
чтобы SSH успел передать подтверждение. Разрыв SSH сам по себе не считается успехом.
«Успешно» появляется после восстановления SSH и изменения Linux `boot_id`:
роутер действительно прошёл новую загрузку. Ожидание ограничено тремя минутами
на роутер. Ошибка пароля/команды, отсутствие туннеля или неподтверждённая загрузка
отображаются отдельно, затем очередь переходит к следующему роутеру.
«Остановить всё» прекращает очередь, но уже отправленный reboot не отменяется;
его неподтверждённый результат помечается явно. Временный каталог reboot в `/tmp`
исчезает при перезагрузке; повторный запрос не запускает эту задачу второй раз.
Пароль остаётся только в памяти worker, очищается в поле после отправки и не
попадает в результаты, БД или browser storage. API перезапуска требует владельца
и тот же CSRF/Origin-контроль, что обновление.
Рядом с «Вернуться в Hub» есть «Обновить информацию о роутерах»: после завершения
очереди кнопка убирает её результаты и получает текущий список, имена и статусы.
Во время работающей очереди она только обновляет статусы, не удаляя задачу.
Обновление списка не запускает установку и не меняет введённую команду.
В карточках отдельно показаны текущий Heartbeat, онлайн/офлайн и последний
сообщённый статус Xray. Они обновляются каждые три секунды и не подменяют
прошлый итог установки. Если Heartbeat устарел, старое состояние Xray явно
помечается как последнее сообщение. Сброс завершённой очереди защищён CSRF и ID:
запрос из старой вкладки не удалит более новую очередь.
Перезапуск Hub прерывает очередь, но уже запущенный installer на роутере
продолжает работу. После перезапуска Hub его итог нужно проверять отдельно.
Роутеры с неработающим обратным SSH-туннелем обновить этим способом нельзя.
Перед запуском списка устройств нет новых требований к их текущему клиенту.

## Установка локальной версии на VPS из Windows PowerShell

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-router-updates.ps1" -Vps "root@193.233.82.38" -Action Install
```

Откат Hub (уже установленные на роутеры версии не откатываются этой командой):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-router-updates.ps1" -Vps "root@193.233.82.38" -Action Rollback
```

Резервная копия: `/opt/owrt-remote/owrt-remote-hub.py.bak-before-router-reboot-all-v121`.
Не устанавливай/не откатывай Hub, пока его очередь работает.

## Проверки

`python -m unittest discover -s tests -p test_router_updates.py -v` проверяет
последовательность, код результата, пароль, отказы подключения, обрыв после
запуска, остановку очереди, повторный запрос, права/CSRF и ограниченный shell
вывод. Реальный task исполняется в MSYS; отсутствующий `setsid` заменён Perl
обёрткой над его POSIX-вызовом. Проверяются остановка группы, локальный тайм-аут
и получение короткого вывода до завершения установки. Синтаксис проверяется
также BusyBox ash. Настоящий Linux `setsid`,
Dropbear и обновление физического OpenWrt требуют проверки пользователем.

`node tests/test_router_updates_ui.cjs` проверяет desktop/mobile, ввод команды,
очистку пароля, итоги, дашборд из 35 устройств, обновление списка и живых статусов,
сохранение раскрытого вывода и возобновление просмотра. Проверяется список
проблемных роутеров, причины, фильтры четырёх категорий и нулевые результаты,
сохранение выбора и прокрутки при автообновлении, безопасный вывод текста и
сброс списка при обновлении роутеров. Дополнительно проверяются мобильные
ширины 320/360/390/430 px, альбомный режим, сохранение настоящей ширины viewport
при длинном тексте, размеры полей/кнопок и отсутствие горизонтального выезда.
Для ПК проверяется центрирование и ограничение ширины 1100 px на экранах
1280/1440/1920 px, а также прежнее расположение кнопок и полей.
Проверки перезапуска используют подставной SSH и безопасный stub `reboot`:
ни тестовая Windows, ни реальные роутеры не перезагружаются. Проверяются новая
загрузка, обрыв SSH без повторной команды, rc ошибки, общий пароль, тайм-аут,
остановка и исключение двух одновременных очередей. Shell проходит BusyBox ash -n.
На экранах 320/390/1280 px проверяются красная кнопка, отдельный POST, очистка
пароля, восстановление просмотра очереди и счётчики. Реальную перезагрузку
OpenWrt и возврат обратного SSH-туннеля нужно проверить на устройстве.
