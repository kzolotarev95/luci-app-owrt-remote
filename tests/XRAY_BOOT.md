# Восстановление Xray после перезагрузки (локальный фикс v120)

В предоставленном журнале node-3 после перезагрузки отсутствовал
`/tmp/owrt-xray/xray`. Повторная загрузка завершилась
`curl: (6) Could not resolve host: github.com`. Heartbeat использует отдельный
процесс и продолжал поступать: статус «онлайн» не подтверждает работу туннеля.
В этой ситуации перезапуск Hub не восстанавливает отсутствующий Xray.

## Изменения клиента

- Исполняемый Xray остаётся в RAM. После установки/обновления сохраняется одна
  сжатая загрузочная копия на проверенном постоянном разделе:
  `/overlay/owrt-remote/xray-cache`, либо `/etc/owrt-remote/xray-cache` при
  непосредственно смонтированном записываемом ext4/UBIFS и подобных ФС.
  Несмонтированный `/overlay`, tmpfs, read-only и перенаправление каталога
  симлинком на RAM не принимаются.
- Кэш ограничен 16 МиБ; при создании сохраняется резерв минимум 2 МиБ.
  Неизменный бинарник не переписывается. Новый файл публикуется атомарным
  переименованием на том же разделе; предыдущая копия удаляется после этого.
  При нехватке места Xray продолжает работать, но автономное восстановление
  после перезагрузки недоступно — это явно записывается в журнал.
- При запуске сначала проверяется кэш для архитектуры устройства. До исполнения
  проверяются gzip, SHA-256 распакованных байтов и размер до 64 МиБ. Изменение
  конфигурации UCI ограничено путём `xray_bin`; клиентский JSON не заменяется
  загрузчиком.
- Без кэша выполняется HTTPS-загрузка. Для curl ограничены время подключения
  (10 секунд), общий бюджет HTTP-загрузки (120 секунд), размер (32 МиБ)
  и число перенаправлений (5). При WAN direct каждый HTTPS-хост, включая
  хост загружаемого файла после редиректа GitHub, разрешается через выбранный
  WAN DNS. Проверка сертификата и исходное имя TLS сохраняются. Системный DNS,
  настройки Podkop и правила маршрутизации не меняются.
- Без curl минимальные HTTPS-загрузчики используют системный DNS, собственный
  тайм-аут и отдельный ограничитель времени на shell. Он не зависит от наличия
  необязательного BusyBox `timeout` и убирает дочерние процессы после завершения.
  В таком режиме нет переопределения DNS для отдельного хоста.
- Рабочий бинарник сохраняется при ошибке сети, пустом/повреждённом ZIP или
  неработающем кандидате. ZIP проверяется до замены; извлекается только
  именованный исполняемый файл. Загрузчики сериализованы блокировкой в RAM.
- Управляемый procd процесс после первых 18 неудач продолжает попытки раз в
  60 секунд, пока Remote включён. Ожидание WAN не расходует попытки запуска.
  Ручные вызовы сохраняют конечное число попыток.
- `install.sh` вызывает `prepare-xray`: использует существующий рабочий Xray
  и подготавливает кэш. Кнопка явной установки Xray по-прежнему загружает релиз.

Запись кэша — однократное изменение Flash при изменении бинарника. Heartbeat
не сжимает Xray и не записывает кэш при каждом запросе.

## Установка из PowerShell Windows 11

Нужен рабочий SSH-доступ именно к целевому роутеру: локальная сеть, отдельный
VPN или восстановленный SSH-туннель. IP `192.168.2.1` — основной роутер
пользователя; это не адрес удалённого node-3.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-boot-fix.ps1" -Router "root@192.168.2.1" -Action Install
```

Скрипт заменяет только `/usr/sbin/owrt-remote`, сохраняет первую резервную
копию в `/root/owrt-remote-backup-before-xray-boot-v120`, подготавливает кэш,
перезагружает отдельный Heartbeat instance и запрашивает запуск Xray, если
тот остановлен при работающем Heartbeat. Здоровый туннель не перезапускается.
`XRAY_BOOT_ROUTER_Install_OK` подтверждает установку кода, а не установление
обратного соединения: готовность туннеля проверяется по карточке и журналу VPS.

Откат возвращает предыдущий агент; рабочий бинарник, кэш и конфигурация
сохраняются. При отсутствии полной резервной копии ничего не заменяется.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-boot-fix.ps1" -Router "root@192.168.2.1" -Action Rollback
```

## Ограничение восстановления node-3

Старый установленный клиент не выполняет команды из Heartbeat. Если доступна
только VPS, а обратные Админка/SSH не работают, этот фикс пока нельзя установить
на node-3. Старый загрузчик может восстановиться сам, если доступность DNS/GitHub
вернётся. В противном случае нужен отдельный доступ к роутеру или человек рядом.
Публикация исходников и обновление только Hub не устанавливают новый клиент.

## Проверки

`tests/test_xray_bootstrap.py`: очистка RAM с сохранением Flash и восстановление
без сети; отсутствие повторной записи; повреждённый gzip/SHA-256; неудачная
загрузка и некорректный ZIP с сохранением работающего Xray; ограничения места,
проверка ФС, редиректы с WAN DNS, тайм-аут и очистка файлов, продолжение попыток,
конкурентный запуск и восстановление устаревших блокировок.

`tests/test_xray_boot_deploy.py`: повторная установка, первый backup, откат,
неполная копия/плохой shell, восстановление после ошибки, сохранение здорового
туннеля и запуск только остановленного instance.

Прогоны выполняются POSIX shell и BusyBox ash на Windows. Проверка Linux
`/proc` и конкурентных процессов выполняется в MSYS; busybox-w32 не предоставляет
Linux `/proc`, поэтому этот адаптер подменяется в его тестах. Проверка на
физическом AX3000T после настоящей перезагрузки ещё необходима.
