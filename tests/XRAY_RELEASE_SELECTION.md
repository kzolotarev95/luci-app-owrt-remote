# Поиск совместимого Xray: локальное исправление v121

## Подтверждённая причина

Прежний загрузчик строил имя APK из закреплённой версии и вывода
`apk --print-arch`. В некоторых OpenWrt 25 этот вывод — общий ABI `mipsel`,
а опубликованный asset называется `...-mipsel_24kc.apk`. Получался URL
несуществующего `...-mipsel.apk`, и GitHub возвращал 404.

В ответе [GitHub Releases API](https://api.github.com/repos/yichya/openwrt-xray/releases)
найден настоящий `openwrt-xray-26.6.27-r1-mipsel_24kc.apk`; скачанный файл
имеет SHA256
`275e6f1141796e057befb0d3b8daa33a3731e22da9d749d6edc0290950dc6c80`,
совпадающий с `digest` asset. Это проверка источника, а не закрепление версии.

`Command failed: Not found` до подготовки Xray соответствует безусловному
`owrt-remote-logs restart` при первой установке: стандартный `restart`
сначала вызывает удаление ещё не зарегистрированной службы через ubus.
Теперь установщик останавливает службу только после успешного `running`,
а затем выполняет `start`. Вывод Netis после исправления нужен, чтобы
исключить дополнительную ошибку на конкретном устройстве.
У rpcd, uhttpd и Remote также проверяется наличие работающего экземпляра:
для первой активации используется `start`, для работающей службы — `reload`.

## Новый механизм

- Приоритет у APK; команды opkg на APK-системе не выполняются.
- Точная архитектура берётся из менеджера пакетов. Общий ABI уточняется
  через `DISTRIB_ARCH` из `/etc/openwrt_release`, без угадывания по `uname`.
- Загружаются реальные Releases и Assets. Порядок JSON и номер ревизии пакета
  не зашиты в код. Обрабатываются до десяти страниц по 20 релизов; временные
  ответы и число запросов ограничены. Если кандидаты не проходят проверку,
  поиск продолжается на следующей странице с более старыми релизами.
  При успешном кандидате лишние страницы не загружаются.
- Draft, prerelease, чужие URL, другой CPU, отсутствие SHA256 и слишком
  большой пакет отклоняются. URL проверяется HEAD перед GET при наличии curl;
  для минимальных клиентов проверкой доступности служит ограниченный GET.
- Для существующего VLESS reverse без TLS исключаются версии с известным
  запретом транспорта (26.7.11+). Это граница совместимости, а не версия
  скачивания. Дополнительно каждый кандидат выполняет настоящий `-test`.
- Проверяются размер и SHA256 пакета, метаданные, ABI и зависимости.
  APK проверяет нативный solver: `apk add --simulate --no-network`.
  Он не устанавливает скачанный пакет. APK извлекается через `apk extract`;
  IPK — в отдельный каталог. Системный `/usr/bin/xray` не перезаписывается.
- Версия исполняемого бинарника должна совпасть с релизом. Его запуск
  проверяет совместимость с ABI/прошивкой, а не только совпадение имени CPU.
- Проверенный сжатый boot-кэш публикуется атомарно на постоянном разделе
  до замены runtime. Кэш проверяется распаковкой и SHA256. Без места или
  доступного постоянного раздела подготовка завершается явной ошибкой.
- Рабочий core используется без повторной загрузки; после перезагрузки
  проверенный кэш восстанавливается без сети/API. Старые имена кэша читаются.
- Ошибки загрузки, распаковки и проверки сохраняют прежний бинарник,
  рабочий JSON и `/etc/config/owrtremote`. Откат локального исправления
  возвращает код агента, сохраняя подготовленный core и boot-кэш.

## Диагностика установщика

`OWRT_REMOTE_INSTALL_DIAGNOSTIC=1 sh install.sh` показывает этап, команду,
rc и отдельные stdout/stderr. При ошибке эти сведения выводятся и без
диагностического режима; последующие критические этапы не выполняются.
Вывод каждого потока ограничен 32 КиБ. Shell xtrace не включается.
Файлы проекта сначала загружаются/копируются во временный файл в каталоге
назначения и заменяются атомарно. Ошибка загрузки не обрезает прежний агент.

После подготовки Xray установщик для уже включённого клиента проверяет JSON,
запуск процесса и Heartbeat. Исходный UCI сохраняется. Первая установка с
`enabled=0` сообщает, что для соединения необходим OpenWrt config из Hub.
Намеренную остановку Xray через Remote установщик уважает.

Диагностика без ключей: `owrt-remote xray-package-diagnostics`.

## Установка локального исправления и откат

Подставить доступный SSH-адрес удалённого роутера вместо `АДРЕС_РОУТЕРА`:

```powershell
$Fix = "C:\Users\k.zolotarev95\Documents\openwrt overlay\vps\deploy-xray-release-fix.ps1"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router "root@АДРЕС_РОУТЕРА" -Action Install
```

Резервная копия: `/root/owrt-remote-backup-before-xray-release-v121`.
Устанавливается агент и выполняется подготовка core/кэша. Рабочий JSON
не пересобирается, туннель этим скриптом не перезапускается. При прерванной
первой установке создаётся отсутствующий web.key; имеющийся ключ сохраняется.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Fix -Router "root@АДРЕС_РОУТЕРА" -Action Rollback
```

## Проверки и ограничения

- `test_xray_release_selection.py`: реальное уточнение CPU/ABI, выбор asset,
  ревизии, пагинация, несовместимый CPU, metadata, dependency solver,
  ошибки API и некорректный JSON.
- `test_xray_bootstrap.py`: SHA256, повреждённый пакет/кэш, HTTP-ошибка,
  переход к следующему asset, отсутствие сети, сохранение старого core,
  офлайн-восстановление после удаления RAM-копии, конкурирующие установки.
- `test_install_diagnostics.py`: повторная установка в изолированный ROOT,
  сохранение UCI, этап/команда/rc/stdout/stderr, остановка после ошибки.
- `test_xray_release_deploy.py`: установка, откат и автоматическое
  восстановление кода при ошибке подготовки.
- Синтаксис и тесты shell проверяются MSYS sh и BusyBox ash на Windows.

Результат локального прогона выбора релизов, bootstrap, проверки конфигурации
и установки/отката: 76 тестов, 70 успешно, 6 пропущены (четыре требуют
внешних настоящих бинарников Xray, два требуют Linux /proc для проверки
дочерних процессов и конкуренции). Эти два сценария отдельно проходили
в MSYS sh. После добавления атомарной установки и выбора start/reload
повторно прошли все 5 тестов установщика. Shell syntax и PowerShell parser
ошибок не обнаружили.

Физического Netis N6 в этой среде нет. Нативные `apk adbdump/extract`,
бинарник Linux/MIPSel, реальная перезагрузка и успешный туннель на
OpenWrt 25.12.2 должны быть подтверждены после установки на устройстве.
Эмуляция перезагрузки в тестах не заменяет эту проверку.
